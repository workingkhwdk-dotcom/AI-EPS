# AI-EPS 수업 도구 (MVP)

AI 활용 확장된 경험 기반 문제해결학습 모형(AI-EPS)을 수업에서 쓰기 위한 웹 서비스입니다.
주제는 "2018년 제주 예멘 난민 신청 논란", AI는 OpenAI GPT, 인프라는 Firebase입니다.

## 구조

```
public/            정적 웹 (Firebase Hosting)
  index.html, app.js     학생용: 수업 코드 입장 → 1~7단계 워크스페이스
  teacher.html, teacher.js  교사용: 수업 생성, 모둠 진행 현황, AI 로그, CSV
functions/         Cloud Functions (서울 리전)
  policy.js        GYR 규칙 엔진 (단위 테스트 있음)
  prompts.js       단계별 시스템 프롬프트
  case.js          제주 예멘 사건, 출처 24건, 자료 기반 페르소나 4명 (출처별 verified 플래그)
  charter.js       상위 AI(사건 규범 감독자)의 규범: 사건 범위, 허용/범위 밖 주제, 인물 규칙
  guard.js         감독자 AI의 검사 프롬프트와 판정 해석, 위반 시 학생용 안내문
  scripts/         export-sources.js: 원문 대조 점검표(docs/PERSONA_SOURCES.md) 생성
docs/PERSONA_SOURCES.md  인물별 근거 진술과 출처 점검표 (수업 전 원문 대조용)
  index.js         createSession, joinSession, getCase, aiRequest
firestore.rules    학생은 자기 모둠의 work만 수정, AI 로그는 서버만 기록
```

### 핵심 원리: GYR을 서버가 강제한다
| 단계 | AI | 서버가 확인하는 선행 조건 |
|---|---|---|
| 1 사건 경험 | ① 인물과 메신저 대화(혼자) → ② 알아낸 점 정리·제출(혼자, AI 없음) → ③ 모둠 문제 정하기(모둠, AI 없음) | 메시지 입력 (사전 질문 없이 바로 대화) |
| 2 원인 탐색 | **차단** | - |
| 3 검증 | 검색 도우미: 알려진 내용 / 확인할 수 있는 곳 / 확실하지 않은 부분 (판정은 학생) | 2단계에서 만든 검증 질문(들은 이야기 + 질문)만 허용 |
| 4 대안 구상 | 서로 다른 관점의 독립 검토자 3명 (강점·약점·질문만) | 모둠 대안 30자 이상 저장 |
| 5 시나리오 | 시나리오 2개 (1·3·5년 후), 작동 기제·의도하지 않은 결과 포함 | 이해관계자 반응 예측 2개 이상 |
| 6, 7 | **차단** | - |

### 모둠 수렴 구조 (개인 → 모둠 → 공동 문제)
1. **① 대화(혼자)**: 각자 다른 인물에게 '누구인지 / 무엇이 힘든지 / 무엇을 바라는지'를 알아냅니다. 예시 질문 버튼이 있습니다.
2. **② 정리·제출(혼자)**: 같은 5칸(누구, 힘든 것, 바라는 것, 기억에 남는 말, 확인할 말)을 쓰고 **제출**합니다. 제출해야 모둠원이 제출한 내용이 보이고, 제출한 내용은 모둠원 화면에 바로 나타납니다.
3. **③ 모둠 문제(모둠, 대면 토의)**: 네 인물을 나란히 놓고 → 같은 점 → 부딪히는 점 → "어떻게 하면 ~하면서도 ~할 수 있을까?" 한 문장 → 점검표 5개 순서로 문제를 정합니다.
4. 정한 문제는 2~6단계 맨 위에 **'우리 모둠의 문제'** 띠로 계속 보이고, 3~5단계 AI에게도 함께 전달됩니다. ②의 '확인할 말'은 2단계 검증 질문 후보로 이어집니다.
- 모둠 칸(‘모둠 공용 · 실시간’ 표시)은 누가 써도 모든 모둠원 화면에 바로 반영되고, 다른 모둠원이 쓰는 칸에는 "✏️ 별명 입력 중"이 보입니다. 내가 쓰고 있는 칸은 덮어쓰지 않습니다.
- 단계마다 맨 위에 **AI 역할 상자**(AI가 하는 일 / 하지 않는 일 / 우리가 하는 일)가 있고, 맨 아래에 **다음·이전 버튼**이 있습니다.
- 교사 화면: 모둠 표의 **산출물**(그 모둠의 1~7단계 전체, 실시간), **단계별 모아 보기**(모든 모둠의 같은 단계 비교). 기록 CSV에도 산출물이 함께 들어갑니다.

학생 브라우저는 OpenAI를 직접 호출하지 않습니다. 모든 호출은 `aiRequest`를 거치며, 입력과 응답이 모두 로그로 저장됩니다.

## 배포 (Firebase 프로젝트: `knue-socialstudies-ai-eps`)

웹 앱 설정(`public/firebase-config.js`)과 프로젝트 ID(`.firebaserc`)는 이미 연결되어 있습니다. 아래는 **선생님 PC에서 한 번만** 하면 되는 작업입니다.

### 1. 콘솔에서 설정 (https://console.firebase.google.com/project/knue-socialstudies-ai-eps)
1. **요금제를 Blaze(종량제)로 전환** — Cloud Functions 배포에 필요합니다. 결제 예산 알림도 설정하세요.
2. **Authentication → 로그인 방법**: *익명*과 *Google*을 사용 설정 (학생은 익명, 교사는 구글 로그인).
3. **Firestore Database 만들기**: 위치는 `asia-northeast3`(서울) 권장, 프로덕션 모드로 시작 (보안 규칙은 배포 시 적용됩니다).
4. Authentication → 설정 → **승인된 도메인**에 `knue-socialstudies-ai-eps.web.app`, `knue-socialstudies-ai-eps.firebaseapp.com`이 있는지 확인 (보통 자동 등록).

### 2. 터미널에서 배포
```bash
git clone https://github.com/workingkhwdk-dotcom/AI-EPS.git && cd AI-EPS
git checkout claude/loving-fermat-vslak3

npm i -g firebase-tools

cd functions && npm install && cd ..

# OpenAI API 키를 비밀값으로 저장 (코드·저장소에 넣지 않습니다)

# 교사 계정·모델·리허설 설정
```

배포가 끝나면 학생용 주소는 `https://knue-socialstudies-ai-eps.web.app/`, 교사용은 `/teacher.html`입니다.

### 교사 계정 관리
교사 자격은 구글 계정의 이메일로 판정하며, 아래 **세 곳 중 한 곳에만 있어도** 교사입니다(대소문자 무시).
1. **관리자(코드에 고정)**: `functions/teachers.js`의 `ADMIN_EMAILS` — `working.khwdk@gmail.com`. 설정을 잘못해도 잠기지 않도록 항상 교사입니다.
2. **Firestore (권장, 재배포 불필요)**: Firebase 콘솔 → Firestore Database → 데이터에서
   - 컬렉션 `config` 만들기 → 문서 ID `teachers` → 필드 이름 `emails`, 유형 **array**, 값에 이메일 문자열을 추가
   - 이메일을 추가하거나 지우면 **즉시 반영**됩니다. (쉼표로 구분한 문자열 필드로 입력해도 됩니다.)
3. **배포 설정**: `functions/.env`의 `TEACHER_EMAILS` (쉼표 목록). 바꾸려면 재배포가 필요합니다.

`config` 컬렉션은 보안 규칙으로 클라이언트 접근이 모두 막혀 있어, 학생이나 교사 화면에서는 읽거나 쓸 수 없고 콘솔과 서버만 다룰 수 있습니다. 수업은 만든 교사 계정 하나에만 연결됩니다.

### 모델 선택 (OpenAI)
`functions/.env`의 `OPENAI_MODEL`로 정합니다. 기본값은 **`gpt-5-mini`**(GPT-5 계열의 균형 모델)입니다.
- GPT-5 계열은 추론 모델이라 `max_tokens`와 `temperature`를 받지 않습니다. 코드(`functions/openai.js`)가 모델 계열에 맞춰 `max_completion_tokens`와 `reasoning_effort`로 자동 변환하며, GPT-4 계열도 그대로 쓸 수 있습니다.
- **용도별로 모델을 나눌 수 있습니다**: `SCENARIO_MODEL`(5단계 시뮬레이션만 더 강한 모델, 예: `gpt-5`), `GUARD_MODEL`(상위 AI 감독자 전용).
- `REASONING_EFFORT`(기본 `low`)는 대화 응답 속도용입니다. 5단계 시뮬레이션은 코드에서 `medium`으로 고정됩니다. 응답이 느리면 `minimal`, 품질이 아쉬우면 `medium`을 시도하세요.
- 정확한 모델명은 OpenAI 대시보드의 Models 페이지에서 확인하세요. 새 버전이 나오면 이름만 바꿔 `firebase deploy --only functions`를 다시 실행하면 됩니다.
- 비용은 모델과 추론 사고량(reasoning 토큰도 출력 토큰으로 과금)에 따라 달라집니다. 1단계 대화는 인물 응답과 감독자 검사로 호출이 2번이므로, 수업 전에 OpenAI 대시보드에서 사용량 한도(Usage limits)를 설정해 두세요.

### 3. 첫 점검
1. `/teacher.html`에서 구글 로그인 → "점검 (교사 전용)" 탭에 인물 4명이 보이는지 확인
2. 수업 만들기 → 6자리 코드 확인 → 다른 기기(휴대폰)에서 `/` 접속해 코드·모둠 번호·별명으로 입장
3. 학생 화면에서 편지를 읽고 인물과 바로 대화, 교사 화면 "수업 현황"에서 접속·단계와 대화 기록, 감독자 판정(`guard`) 확인
4. 리허설이 끝나면 `functions/.env`의 `ALLOW_UNVERIFIED_PERSONAS`를 지우거나 `false`로 바꾸고 `firebase deploy --only functions`

> Analytics는 연결하지 않았습니다(학생 대상 서비스). 웹 설정값의 `apiKey`는 프로젝트 식별용 공개 값이며, 접근 통제는 Firestore 보안 규칙과 Cloud Functions가 담당합니다.

## 수업 진행

1. `/teacher.html` → **새 수업** 탭에서 모둠 수를 정해 수업 만들기 → 6자리 수업 코드 확인
2. 학생에게 `/` 주소, 수업 코드, 모둠 번호를 안내 (학생은 별명으로 입장, 로그인 불필요)
3. **수업 현황** 탭에서 실시간으로 확인:
   - 접속 중인 학생 수, 학생별 **현재 단계·접속 상태(자리 비움 시간)·AI 대화 수**, 배정된 인물(교사만 보임)
   - 모둠별 산출물 진행(1~7단계 점), AI 호출 수, **감독자 개입 수**, AI 오류 표시
   - "대화 보기"(학생별 인물 대화와 감독자 판정), "모둠 기록"(3~5단계 AI 기록), 기록 CSV
4. 인물·자료의 근거와 출처는 **점검 (교사 전용)** 탭에만 있습니다(접혀 있음). 학생에게는 보이지 않습니다.

## 자료 기반 페르소나 4명 (중요)

| 인물 | 축 | 융합한 자료 유형 |
|---|---|---|
| 예멘에서 온 난민신청자 | 당사자 | 신청자 인터뷰(서울신문, 머니투데이, 알자지라), 인권위 상담 결과 |
| 불안해하는 제주 도민 | 반대·우려 | 상인 인터뷰, 반대 집회 주최·참가자 발언, 청원·여론 보도 |
| 난민 지원 단체 활동가 | 지원 | 제주예멘난민대책위, 이주민센터, 난민인권센터, 인권단체, 지원 현장 |
| 출입국·행정 담당자 | 제도 | 제주출입국·외국인청 일문일답, 법무부 발표, 제주도 대응, 청와대 답변 |

- 같은 유형의 여러 인터뷰는 한 인물로 **융합**했고, 근거는 `case.js`의 `basis`에 적혀 있습니다. 인물에게는 **사람 이름**(아델, 미경, 서진, 정민호)을 붙였고 설정(`setting`)과 말투(`voice`)가 있습니다. 이름·설정은 수업용 창작이며 특정 실존 인물을 나타내지 않습니다.
- 진술마다 **종류**(증언 / 사실 / 주장 / 의견)와 출처가 붙어 있습니다. 인물은 주장·의견을 사실처럼 단정하지 않고 "~라고 들었어요"처럼 말합니다.
- **학생에게 보이는 것**: 객관적 사건 개요, 인물의 **이름과 편지**(그 사람의 입장을 담은 가상 편지), 실제 자료(카테고리별). 인물의 역할·근거·출처·다른 모둠원의 인물은 보이지 않고, 학생은 대화하면서 누구인지 알아냅니다.
- **대화 방식**: 인물은 끝까지 그 사람인 것처럼 1~3문장으로 짧게, 이모지와 함께 말하고, **학생이 물어본 것에만** 답합니다. 출처 번호나 "수업용 인물" 같은 말은 하지 않습니다. 학생이 진지하게 진짜 사람인지 물으면 가상의 인물임을 밝힙니다.
- **지어내기 규칙**: 사소한 일상·기분은 근거와 어긋나지 않게 자연스럽게 지어낼 수 있지만(이 인물 한 사람의 경우로만), 수치·날짜·법과 제도·공식 결정·심사 결과 같은 **핵심 사실은 근거 진술에 있는 것만** 말하고 없으면 그 사람 입장에서 "잘 모르겠어요"라고 답합니다.
- 대화 시점은 **2018년 12월(심사 결과 발표 직후)** 입니다. 아델은 심사 대상 다수가 받은 **인도적 체류 허가** 상태로 설정했습니다(`setting`).
- **모둠원마다 서로 다른 인물이 자동 배정**됩니다(교사 화면에서만 확인). 학생은 알아낸 점을 "내 말로" 적어 모둠에 공유합니다. 모둠원이 5명 이상이면 인물이 겹칩니다. 학생별 대화는 본인과 교사만 읽을 수 있습니다.

### 상위 AI(사건 규범 감독자)

인물 AI 위에 규범을 가진 감독 층이 있습니다(`charter.js`, `guard.js`).
1. **생성 단계**: 모든 인물 프롬프트에 규범이 들어갑니다 — 사건 범위(2018 제주 예멘), 허용 주제, 범위 밖 주제(다른 난민 사건, 현재 정치 예측, 종교·민족 일반 논쟁 등), 날조·단정·비하·결론 유도 금지.
2. **검사 단계**: 인물의 응답이 학생에게 가기 전에 감독자 AI가 `scope`(범위 이탈) / `fabrication`(근거 없는 핵심 사실) / `kind`(주장을 사실처럼) / `overshare`(묻지 않은 정보·과다 응답) / `meta`(AI·자료 언급) / `hate` / `advice` / `personal_info` 위반 여부를 검사합니다.
   - **가벼운 위반**(fabrication, kind, overshare, meta)은 감독자가 **같은 인물 말투로 고쳐 쓴** 응답을 학생에게 보냅니다.
   - **무거운 위반**(범위 이탈, 비하, 결론 유도, 개인정보)이나 검사 실패는 인물 말투의 짧은 안내("그건 제가 잘 아는 얘기가 아니에요 🙂")로 대체합니다. 학생은 AI가 끼어들었다는 것을 느끼지 않고 대화를 이어 갑니다.
   - **원래 응답과 위반 사유는 교사용 기록(`guard`)에만** 남습니다. 감독자 호출이 실패하거나 응답 형식이 깨지면 안전 쪽(안내)으로 처리합니다.
3. 1단계 대화는 호출이 2번(인물 + 감독자) 일어나므로 비용이 약 2배입니다.
4. 한계: 감독자도 AI라 오판할 수 있습니다. 수업 전 리허설에서 범위 밖 질문, 비하 유도 질문, 자료에 없는 질문을 직접 던져 보고, 교사 로그의 `guard` 기록을 점검하세요.

### 원문 대조 (필수)

**근거 진술은 AI가 검색 결과 요약을 바탕으로 정리했고 원문을 직접 열람하지 못했습니다.** 모든 출처는 `verified:false`이며, 이 상태에서는 학생에게 인물이 노출되지 않습니다.
1. `docs/PERSONA_SOURCES.md`(또는 교사 화면의 "점검 (교사 전용)" 탭)에서 출처 링크를 열어 진술과 대조합니다.
2. 틀린 진술은 `functions/case.js`에서 고치고, 확인한 출처는 `verified: true`로 바꿉니다(`SOURCES`의 각 항목, 또는 파일 끝 일괄 `false` 설정 줄을 조정).
3. `cd functions && npm run export-sources > ../docs/PERSONA_SOURCES.md`로 점검표를 갱신하고 배포합니다.
- 리허설은 `functions/.env`에 `ALLOW_UNVERIFIED_PERSONAS=true`를 넣으면 대조 전 인물도 보입니다. 실제 수업 전에는 지우세요.
- 출처 제목 중 일부(J15, J17)는 설명 문구이며 실제 제목이 아닙니다.
- 아직 없는 관점: 어선·양식장 **고용주**(직접 인터뷰 자료 부족), 난민 인정자 본인의 장기 정착 증언. 자료를 찾으면 인물과 출처를 `case.js`에 추가하세요.
