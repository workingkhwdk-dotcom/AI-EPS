# AI-EPS: 확장된 경험 기반 문제해결학습 모형 — 수업 도구 (MVP)

**AI-EPS: 확장된 경험 기반 문제해결학습 모형**을 수업에서 쓰기 위한 웹 서비스입니다(한국교원대학교).
교사가 수업을 만들 때 사건을 고릅니다(아래 [수업 사건](#수업-사건)). AI는 OpenAI GPT, 인프라는 Firebase입니다.

## 구조

```
public/            정적 웹 (Firebase Hosting)
  index.html, app.js     학생용: 수업 코드 입장 → 1~7단계 워크스페이스
  teacher.html, teacher.js  교사용: 수업 생성, 모둠 진행 현황, AI 로그, CSV
  m.html, m-teacher.html    모바일 전용 화면(학생·교사). 같은 app.js·teacher.js 로 움직이고 배치만 휴대폰에 맞춤(mobile.css)
  device.js        휴대폰으로 PC 화면을 열면 모바일 화면으로 자동 이동(?view=pc 로 PC 화면 고정, ?view=m 으로 되돌림)
functions/         Cloud Functions (서울 리전)
  policy.js        GYR 규칙 엔진 (단위 테스트 있음)
  prompts.js       단계별 시스템 프롬프트
  case.js          사건 모음: cases/*.js 를 합치고 자료·인물 사용 가능 여부(출처 verified)를 계산
  cases/           사건별 파일. 출처·사건 개요·공통 배경·범위·인물 9명(4개 축)·2단계 자료
    jeju2018.js    제주 예멘 난민 신청 논란 (2018), 출처 J1~J24
    waste2019.js   한국 쓰레기 필리핀 불법 수출·반송 논란 (2018~2019), 출처 W1~W20
    school2018.js  서울 강서 특수학교 설립 갈등 (2017~2018), 출처 S1~S13
    junam2025.js   창원 주남저수지 보전과 개발 갈등 (2021~2025), 출처 JN1~JN20
    changwon2025.js 창원 인구 100만 붕괴와 청년 유출 (2024~2025), 출처 P1~P19
  charter.js       상위 AI(사건 규범 감독자)의 규범: 사건 범위(사건 파일의 scope + 공통 범위), 인물 규칙
  guard.js         감독자 AI의 검사 프롬프트와 판정 해석, 위반 시 학생용 안내문
  scripts/         export-sources.js: 원문 대조 점검표(docs/PERSONA_SOURCES.md) 생성
docs/PERSONA_SOURCES.md  인물별 근거 진술과 출처 점검표 (수업 전 원문 대조용)
  index.js         createSession, joinSession, getCase, aiRequest
firestore.rules    학생은 자기 모둠의 work만 수정, AI 로그는 서버만 기록
```

### 모바일 전용 화면
- 휴대폰(아이폰·안드로이드 폰)으로 `/`(학생)나 `/teacher.html`(교사)을 열면 `m.html`, `m-teacher.html`로 자동으로 옮겨 갑니다. 태블릿과 PC는 그대로입니다. 입장 안내문의 주소는 그대로 쓰면 됩니다.
- 학생 모바일: 1~7단계 이동은 화면 아래 막대, 대화 입력창은 막대 바로 위에 붙고, 글을 쓰는 동안에는 막대가 숨어 키보드 위 공간이 넓어집니다.
- 교사 모바일: 학생·모둠 표가 카드로 바뀌고, 수업 안의 메뉴(진행 현황·자료 관리·인물 편집·수업 설정)는 아래 막대로 엽니다. 휴대폰 브라우저가 구글 로그인 팝업을 막으면 같은 창에서 로그인합니다.
- 화면 맨 아래 **PC 화면으로 보기**를 누르면 그 기기에서는 PC 화면을 기억하고, PC 화면 아래의 **모바일 화면으로 보기**로 되돌립니다.
- 학습 활동 공간을 넓히기 위해 모바일 학생 화면은 머리글·아래 막대를 얇게 하고, **아래로 스크롤하면 둘 다 숨고 위로 스크롤하면 다시 나옵니다**(교사 화면은 숨기지 않음). 1단계 대화는 대화창이 화면 대부분을 쓰고, 알아낼 것(누구인지·힘든 것·바라는 것)이 한 줄 칩으로, 남은 질문 수가 입력창 위에 항상 보입니다. 2단계 실제 사건 자료는 펼친 채로 시작합니다.
- 두 화면은 같은 id 를 써야 합니다. 한쪽 HTML에 칸을 추가하면 다른 쪽에도 넣으세요(화면 테스트가 확인합니다).

### 체험하기(demo) — 서버 없이 학생 화면을 혼자 해 보기
- 주소: `/demo.html`. 5개 주제(사건) 중 하나를 골라 학생 화면을 처음부터 끝까지 혼자 체험한다. 입장·로그인 없이 바로 열린다.
- **저장은 서버가 아니라 이 기기(localStorage)** 에 주제별로 따로 한다. 화면 위쪽 **홈**은 주제 고르는 메뉴로, **초기화**는 그 주제를 처음부터 다시 하게 한다(쓴 글·대화·단계 안내 본 기록 삭제).
- 학생 화면(`app.js`)을 그대로 쓴다. 대신 `demo-play.html`(PC)·`demo-play-m.html`(휴대폰)이 Firebase 모듈을 `public/demo/stubs/` 의 가짜(import map)로 바꿔, `public/demo/server.js`(가짜 서버)가 `getCase`·`choosePersona`·`aiRequest` 를 브라우저 안에서 처리한다. Firebase SDK 는 부르지 않는다(AI 호출만 위 `demoRequest`).
- **AI 답은 실제 수업과 같은 AI다.** 화면이 서버 함수 `demoRequest`(`functions/demo.js`, 로그인 없이 HTTP 로 부름)에게 묻고, 서버는 실제와 같은 인물 프롬프트·상위 AI(감독자)·3~5단계 프롬프트를 쓴다. 웹 검색은 쓰지 않는다(3단계는 수업 자료만 근거). 쓴 글은 요청에 실려 오고 서버에는 저장하지 않는다.
- **횟수·비용 보호:** 기기(localStorage 의 `eps_demo_device`)·주제마다 인물 질문 5번, 2~5단계 AI 5번(`demoUsage/{기기}` 에 서버가 센다. 초기화해도 돌아오지 않는다. 실패한 호출은 돌려준다). 하루 전체 한도 `DEMO_DAILY_CAP`(기본 300), 모델 `DEMO_MODEL`(비우면 `OPENAI_MODEL`)은 `functions/.env` 로 바꾼다. 화면의 안내 띠·메뉴·단계마다 붙는 '데모라서' 줄(`demo/ui.js`)에도 실제와 다른 점을 적어 두고, 준비된 예시 답·웹 검색 없이 답한 3단계 답에는 답 안에도 표시가 붙는다. 체험이 실제와 달라지는 기능을 더하거나 고치면 `DIFF` 문구도 함께 고칠 것. OpenAI 키 쪽 사용 한도도 함께 걸어 둘 것.
- 횟수를 다 썼거나, 서버가 배포 전이거나, 연결이 안 되면 **준비된 예시 답**으로 대신한다(인물의 말은 인물 자료에서 질문과 가까운 것을 골라 들려 주고 — `public/demo/chat.js`, 3~5단계는 모둠이 쓴 글과 수업 자료로 짜 맞춘 예시). 안내 알림이 뜬다.
- 배포: `firebase deploy --only functions:demoRequest,hosting` (함수를 먼저 배포하지 않아도 체험은 준비된 답으로 동작한다).
- 데이터·화면 파일은 만들어서 쓴다: `node tools/build-demo-data.js` → `public/demo/data/*.json`, `topics.json`, `demo-play*.html`. **`functions/cases` 나 `index.html`·`m.html` 을 고치면 이 명령을 다시 실행해 결과를 함께 커밋**한다(테스트가 id 가 어긋나면 알려 준다). 학생에게 보이지 않는 교사 전용 정보(역할·근거·출처)는 내보내지 않는다.

### 아이콘(브라우저 탭·휴대폰 홈 화면)
- 학생용(파란 바탕, 초록 말풍선)과 교사용(초록 바탕, 남색 체크)이 따로 있습니다. 둘 다 교원대 마크, 사회과를 뜻하는 지구 격자, `AI-EPS` 글자를 담았습니다. 파일은 `public/icons/`, 홈 화면 추가 설정은 `public/manifest-student.webmanifest`, `manifest-teacher.webmanifest`입니다.
- 학생 화면(`index.html`, `m.html`)과 교사 화면(`teacher.html`, `m-teacher.html`)이 각자의 아이콘과 이름('AI-EPS', 'AI-EPS 교사')을 연결합니다. 휴대폰 브라우저의 **홈 화면에 추가**(아이폰은 공유 → 홈 화면에 추가)를 누르면 이 아이콘으로 추가됩니다. 이미 추가해 둔 것은 지우고 다시 추가해야 새 아이콘으로 바뀝니다.
- 아이콘을 고치려면 `tools/make-icons.py`의 색·배치를 바꾸고 `pip install pillow numpy` 후 `python3 tools/make-icons.py`를 실행합니다(마크 원본: `tools/icon-src/knue-mark.png`).

### 수업 시작(대기실)과 학생 안내
- 수업을 만들면 **대기 중** 상태입니다. 학생은 입장할 수 있지만 활동 화면 대신 대기 화면(모둠·별명, 질문 횟수만)을 봅니다. 서버도 시작 전에는 AI 요청을 막습니다.
- 교사는 수업 화면 맨 위 **대기실** 카드에서 모둠별 입장 현황(접속 상태 점)을 보고, 모둠을 잘못 들어온 학생은 이름 옆 **이동**으로 옮긴 뒤 **수업 시작하기**를 누릅니다. 시작하면 학생 화면이 저절로 활동 화면으로 바뀌고 되돌릴 수 없습니다.
- 값이 없는 예전 수업은 시작된 것으로 봅니다. 복제한 수업은 다시 대기 중으로 만들어집니다.
- 학생은 각 단계(1단계는 ①②③마다)에 처음 들어갈 때 **무엇을·어떻게** 안내 팝업을 봅니다. **이해했어요**를 누르면 바로 활동하고, **이해 못했어요**를 누르면 더 자세한 설명이 나옵니다. 본 안내는 그 기기에 기억해 다시 뜨지 않고, 위쪽 **?** 버튼으로 다시 봅니다. 안내 글은 `public/help.js`에서 고칩니다.
- 학생은 위쪽 **로그아웃**으로 나갈 수 있습니다(실수 방지 확인이 한 번 나옵니다). 선생님이 모둠을 옮기면 학생 화면은 로그아웃되지 않고 새 모둠으로 저절로 다시 열립니다.

### 인물 대화의 감독(느슨한 기준)
- 질문 횟수가 제한되어 있으므로 감독 기준을 느슨하게 둡니다. 인물 자신에 대한 질문(성별·나이·가족·고향·하는 일 등)과 가벼운 잡담에는 진짜 사람처럼 답합니다. 아주 노골적인 성적·폭력적 내용으로 몰아가는 경우, 숙제 대행·코딩처럼 대화와 완전히 무관한 요청, 다른 사건·현재 정치 등을 길게 논하는 경우, 학생의 개인정보를 묻는 경우에만 막습니다. 기준은 `functions/charter.js`, `functions/guard.js`, `functions/prompts.js`에 있습니다.

### 핵심 원리: GYR을 서버가 강제한다
| 단계 | AI | 서버가 확인하는 선행 조건 |
|---|---|---|
| 1 사건 경험 | **인물 고르기**(모둠이 모든 인물의 편지를 읽고 상의해 한 명씩 선택) → ① 고른 인물과 메신저 대화(혼자) → ② 알아낸 점 정리·제출(혼자, AI 없음) → ③ 모둠 문제 정하기(모둠, AI 없음) | 메시지 입력, **학생별 질문 횟수**(기본 5번, 교사가 수업마다 1~50번으로 정함) |
| 2 원인 탐색 | **생각 도우미(질문만)**: 학생이 쓴 '처음 내 생각 돌아보기'나 모둠의 원인 추측을 읽고 유형을 가려(예: 멀리 둠·겉모습만 닮음·한쪽만 봄·판단부터 함 / 한 군데만 봄·누군가를 탓함·한 사람 말에만 기댐) 그에 맞는 **질문 하나만** 돌려줌. 답·예시·칭찬·설계 용어는 쓰지 않음. 교사가 수업마다 끌 수 있고, 학생 1명당 8번까지이며 모둠의 3~5단계 한도는 쓰지 않음 | 내가 쓴 연결(남의 글 불가)이 8자 이상 / 원인 도우미는 모둠 문제 + 원인 2개 이상 |
| 3 검증 | 검색 도우미: 알려진 내용 / 확인할 수 있는 곳 / 확실하지 않은 부분 (판정은 학생). **2단계 수업 자료와 웹 검색 결과에만 근거**하고 문장마다 근거를 표시, 웹 출처 링크를 남김 | 1단계 ③ 모둠 문제 + 2단계에서 만든 검증 질문(자료와 먼저 비교한 결과 포함)만 허용 |
| 4 대안 구상 | 서로 다른 관점의 독립 검토자 3명 (강점·약점·질문만). 대안이 3단계 핵심 원인을 줄이는지도 짚음. 다른 나라 사례 카드 5개(출처 링크)를 참고할 수 있다 | 3단계 ③ 핵심 원인 + 모둠 대안 30자 이상 저장 (겨냥하는 원인·참고한 사례를 함께 적음) |
| 5 시나리오 | 시나리오 2개 (1·3·5년 후), 작동 기제·의도하지 않은 결과 포함. 핵심 원인이 어떻게 달라지는지와 이어서 씀 | 4단계 ② 최종 대안 30자 이상 + 이해관계자 반응 예측 2개 이상 |
| 6, 7 | **차단** (7단계: 2018년 이후 실제 전개와 우리 시나리오를 비교) | - |

### 모둠 수렴 구조 (개인 → 모둠 → 공동 문제)
1. **① 대화(혼자)**: 대화를 시작하기 전에 사건마다 정한 질문(예: "'난민'이라는 말을 들으면 어떤 사람이 먼저 떠오르나요?")에 **처음 내 생각**을 한 줄 적습니다(나만 봄, 적어야 첫 질문을 보낼 수 있음). 그다음 각자 다른 인물에게 '누구인지 / 무엇이 힘든지 / 무엇을 바라는지'를 알아냅니다. 예시 질문 버튼이 있습니다.
2. **② 정리·제출(혼자)**: 6칸(누구, 힘든 것, 바라는 것, **'어, 내 생각과 다르네' 싶었던 순간**, 기억에 남는 말, **'정말 그럴까?' 싶었던 말**)을 쓰고 **제출**합니다. 제출해야 모둠원이 제출한 내용이 보이고, 제출한 내용은 모둠원 화면에 바로 나타납니다.
3. **③ 모둠 문제(모둠, 대면 토의)**: 네 인물을 나란히 놓고 → 같은 점 → **서로 다르게 말한 것**(누가 맞는지는 2·3단계에서 확인) → 부딪히는 점 → "어떻게 하면 ~하면서도 ~할 수 있을까?" 한 문장 → 점검표 5개 순서로 문제를 정합니다.
4. 이후 단계는 앞 단계의 결과를 받아 이어집니다.
   - 2단계: ① **처음 내 생각 돌아보기**(대화 전 생각과 '어?' 했던 순간에서 출발해 → 그 생각은 어디서 왔을까 → 내 생활에서 닿아 있는 장면(그 사람 쪽 / 걱정하는 쪽 / 나도 모르게 이어져 있는 것 중 하나) → 그래서 궁금해진 것) + 생각 도우미의 질문과 '더 생각한 것' → ② 왜 이런 일이 생겼을까(사람들의 생각·선택 / 동네·사회 분위기 / 법·제도·규칙, ①의 궁금한 것을 후보로) → ③ '정말 그럴까?' 확인할 질문(정말 그럴까 싶은 말·인물들이 엇갈린 말을 후보로)
   - 연결 활동을 '인물과 나의 비슷한 점 찾기'로 하지 않는 이유: 비슷한 점을 억지로 찾으면 기계적이 됩니다. 듀이의 문제 해결처럼 **내가 당연하게 믿어 온 것이 흔들리는 순간**에서 출발해, 그 믿음이 어디서 왔는지를 돌아보며 남의 문제를 내 문제로 끌어옵니다. 7단계에서 '처음 내 생각은 어떻게 바뀌었나요?'로 다시 돌아봅니다.
   - 3단계: ① 검증 질문마다 AI에게 묻고 판정 → ② 우리 추측(원인)마다 검증 판정을 보고 '뒷받침됨 / 약함 / 버림' → ③ 남긴 원인으로 핵심 원인
   - 4단계: 핵심 원인을 보고 대안 → AI 검토 → 최종 대안(문제 질문의 두 바람을 모두 다루는지 점검)
   - 5단계: **최종 대안**을 기준으로 반응 예측과 시뮬레이션(후보 대안도 선택 가능) → 예상되는 문제
   - 6단계: 최종 대안과 예상 문제를 보고 계획 → 7단계: 문제 → 원인 → 대안 → 예상 문제 → 계획을 한 줄씩 모아 보고, 빈 곳은 해당 단계로 돌아가 고침
5. 정한 문제는 2~6단계 맨 위에 **'우리 모둠의 문제'** 띠로 계속 보이고, 3~5단계 AI에게도 함께 전달됩니다. ②의 '확인할 말'은 2단계 검증 질문 후보로 이어집니다.
- 모둠 칸은 누가 써도 모든 모둠원 화면에 바로 반영되고, 다른 모둠원이 쓰는 칸에는 "✏️ 별명 입력 중"이 보입니다. 내가 쓰고 있는 칸은 덮어쓰지 않습니다.
- 단계마다 맨 위에 **AI 역할** 한 줄(누르면 AI가 하는 일 / 하지 않는 일 / 우리가 하는 일)이 있고, 맨 아래에 **다음·이전 버튼**이 있습니다.

### 화면 글 원칙: 설명은 줄이고, 그때그때 다음 할 일만
- 방법 설명은 **단계 안내 팝업**(처음 들어갈 때, **?** 버튼)에만 둡니다. 단계 화면에는 설명 문단을 두지 않고, 칸 이름과 예시 문구(placeholder)로 충분하게 씁니다.
- 대신 단계 맨 위의 **지금 할 일** 한 줄이 모둠이 쓴 내용을 보고 다음에 할 일 하나만 알려 줍니다(예: "① 검증 질문을 AI에게 물어봐요 (1/3)"). 앞 단계가 비어 AI가 잠겨 있으면 그 이유와 **바로 가기**를 보여 줍니다. 규칙은 `public/app.js` 의 `STEP` 에 있습니다.
- 단계를 마치면 지금 할 일이 **✓ 완료**로 바뀌고, 단계 탭에 체크가 붙고, **다음** 버튼이 강조됩니다(덜 했으면 옅은 버튼).
- 좋은 예·나쁜 예는 **예시 보기**로 접어 둡니다. 경고는 조건이 맞을 때만 뜹니다(예: 최종 대안이 '한쪽만 다룬다').
- 1단계 대화는 '알아낼 것' 칩과 남은 질문 줄이 안내를 맡고, 두 번 이상 물어보면 그 줄에 **② 정리로** 바로 가기가 생깁니다.
- 교사 화면도 입력칸 설명을 없애고, 필요한 설명은 해당 버튼의 확인 창에 둡니다. 정리 시간에만 쓰는 **단계별 모아 보기**는 접어 둡니다.

### 작은 디테일
- **입장**: 수업 코드는 소문자·띄어쓰기를 알아서 고치고 6자를 다 쓰면 모둠 번호 칸으로 넘어갑니다(코드에는 헷갈리는 0·O·1·I 가 없습니다). 교사 화면의 **QR**(주소 `/?code=코드`)을 찍으면 코드가 채워진 채로 열립니다. 이 탭에서 다시 들어올 때는 코드·모둠이 채워져 있고, 자동 로그아웃(오래 안 씀 등)이었다면 별명까지 남아 비밀번호만 치면 됩니다. 직접 로그아웃하면 다음 사람을 위해 별명은 지웁니다. 한글을 조합하는 중의 Enter 는 입장으로 보지 않습니다.
- **대기실**: 우리 모둠에 들어온 친구 별명이 실시간으로 보입니다(모둠 문서의 `names`, 서버가 입장·이동 때 적음. 인물 정보는 없음).
- **1단계**: 처음 받는 편지는 도착하듯 내려앉고(안내 창이 떠 있는 동안은 기다림), 질문이 하나 남으면 "마지막 질문이에요"를 미리 보여 줍니다.
- **모둠 활동**: 모둠원이 방금 바꾼 칸과 새 항목은 잠깐 반짝입니다. 모두 ② 정리를 제출하면 "③으로" 버튼이 달린 알림이 뜨고, 방금 마친 단계 탭은 한 번 톡 튑니다.
- **삭제**는 확인 창 없이 바로 지우고 5초 동안 **되돌리기**를 줍니다.
- 교사 화면도 같습니다. **자료·분류 삭제**, **기본 자료로 되돌리기**, **인물 원래대로 되돌리기**는 묻지 않고 바로 하고 8초 동안 **되돌리기**를 줍니다. 되돌릴 수 없는 일(비밀번호 지우기, 수업 복제)은 브라우저 기본 창 대신 화면 안의 확인 창으로 묻고, **수업 삭제**는 수업 코드를 직접 쳐야 삭제 버튼이 눌립니다(창 안에서 기록 CSV도 바로 받을 수 있음).
- **최소 글자 수**(대안·최종 대안 30자, 문제 질문·핵심 원인 10자)는 쓰는 동안 `18 / 30자`로 보이고 채우면 초록색 ✓ 가 됩니다. 글 칸은 내용에 따라 늘어납니다.
- **Enter**: 추가 칸에서 Enter 를 누르면 다음 칸으로 가거나 바로 추가됩니다. 휴대폰 키보드에도 '다음/완료'가 맞게 보입니다.
- **AI를 기다리는 동안** 모둠이 먼저 해 볼 일을 한 줄 보여 줍니다.
- **교사**: 수업 코드 옆 QR, **크게 띄우기**(교실 화면에 주소·코드·QR·입장 인원만 크게, Esc 로 닫기), **학생에게 한마디**(모든 모둠 또는 한 모둠, 학생 화면 위쪽 띠로 뜨고 학생이 닫으면 같은 말은 다시 안 뜸), **10분 넘게 그대로인 모둠** 표시(산출물·AI 사용·인물 대화 수 기준, 교사 화면을 연 뒤부터 셈, 학생이 접속 중인 모둠만), **수업 닫기** 전에 접속 중인 학생 수와 7단계를 마치지 않은 모둠을 보여 줍니다.
- QR 은 `public/vendor/qrcode.js`(qrcode-generator 1.4.4, MIT)를 그대로 넣어 외부 서버 없이 만듭니다.
- 교사 화면: 모둠 표의 **산출물**(그 모둠의 1~7단계 전체, 실시간), **단계별 모아 보기**(모든 모둠의 같은 단계 비교). 기록 CSV에도 산출물이 함께 들어갑니다.

학생 브라우저는 OpenAI를 직접 호출하지 않습니다. 모든 호출은 `aiRequest`를 거치며, 입력과 응답이 모두 로그로 저장됩니다.

## 배포 (Firebase 프로젝트: `knue-socialstudies-ai-eps`)

웹 앱 설정(`public/firebase-config.js`)과 프로젝트 ID(`.firebaserc`)는 이미 연결되어 있습니다. 아래는 **선생님 PC에서 한 번만** 하면 되는 작업입니다.

3. **Firestore Database 만들기**: 위치는 `asia-northeast3`(서울) 권장, 프로덕션 모드로 시작 (보안 규칙은 배포 시 적용됩니다).

### 교사 계정 관리
교사 자격은 구글 계정의 이메일로 판정하며, 아래 **세 곳 중 한 곳에만 있어도** 교사입니다(대소문자 무시).
1. **코드에 고정**: `functions/teachers.js`의 `ADMIN_EMAILS`(관리자 `working.khwdk@gmail.com`, 설정을 잘못해도 잠기지 않도록 항상 교사)와 `FIXED_TEACHERS`(`ccchoihy@gmail.com`). 바꾸려면 재배포가 필요합니다.
2. **Firestore (권장, 재배포 불필요)**: Firebase 콘솔 → Firestore Database → 데이터에서
   - 컬렉션 `config` 만들기 → 문서 ID `teachers` → 필드 이름 `emails`, 유형 **array**, 값에 이메일 문자열을 추가
   - 이메일을 추가하거나 지우면 **즉시 반영**됩니다. (쉼표로 구분한 문자열 필드로 입력해도 됩니다.)
3. **배포 설정**: `functions/.env`의 `TEACHER_EMAILS` (쉼표 목록). 바꾸려면 재배포가 필요합니다.

`config` 컬렉션은 보안 규칙으로 클라이언트 접근이 모두 막혀 있어, 학생이나 교사 화면에서는 읽거나 쓸 수 없고 콘솔과 서버만 다룰 수 있습니다. 수업은 만든 교사 계정 하나에만 연결됩니다. 교사 판정은 **인증된 이메일**(Google 로그인)만 이메일로 인정하므로, 이메일/비밀번호 가입을 켜도 남의 교사 이메일로 가입해 교사가 될 수 없습니다(이메일·비밀번호 계정은 아래 두 경우만 교사).

**이메일·비밀번호 교사 계정**(구글 계정이 아닌 경우, 예: `teacher@knue.com`)
1. Firebase 콘솔 → Authentication → 로그인 방법에서 **이메일/비밀번호**를 켜고, 사용자 탭에서 계정을 만듭니다.
2. 그 이메일을 `functions/teachers.js`의 `PASSWORD_TEACHERS`에 넣고 functions를 배포합니다. 콘솔에서 만든 계정은 이메일 인증 표시가 없어서, 이 목록에 있는 이메일·비밀번호 계정만 예외로 교사로 인정합니다.
3. 교사 화면 로그인 카드 아래쪽 **이메일로 로그인**에서 들어갑니다.
4. 계정을 콘솔에서 지우면 `PASSWORD_TEACHERS`에서도 지우고 재배포하세요(지운 뒤 다른 사람이 같은 이메일로 가입해 교사가 되지 않게).

**교사용 계정 만들기 (선생님이 직접 가입)**
교사 화면 로그인 카드의 **교사용 계정 만들기**(또는 `/teacher.html#signup`)에서, 연수·안내에서 받은 **교사 인증 문구**를 넣으면 관리자 손을 거치지 않고 교사가 됩니다.
1. 준비: `functions/.env`에 `TEACHER_SIGNUP_CODE=문구`를 적고 functions를 배포합니다. 문구는 코드·저장소에 두지 않습니다. 비워 두면 가입이 꺼집니다.
2. 이메일·비밀번호로 가입하게 하려면 Firebase 콘솔 → Authentication → 로그인 방법에서 **이메일/비밀번호**를 켜 둡니다.
3. 가입 방법
   - **구글 계정**: 구글로 로그인 → 인증 문구 입력 → 승인되면 그 이메일이 `config/teachers`의 `emails`에 들어갑니다.
   - **이메일·비밀번호**: 이메일(아이디)·비밀번호(8자 이상)·인증 문구를 넣고 '계정 만들기'를 누릅니다. 문구가 맞으면 그 **계정**(uid)이 `teacherAccounts/{uid}`에 승인됩니다. 문구가 틀리면 방금 만든 계정은 바로 지워집니다. 이메일·비밀번호 계정은 이메일 인증 표시가 없어서 이메일이 아니라 계정으로 승인하므로, 남의 교사 이메일로 새 계정을 만들어도 문구 없이는 교사가 될 수 없습니다.
   - 이미 로그인했지만 교사가 아닌 계정은 첫 화면에서 인증 문구 입력 칸만 보입니다.
4. 문구를 맞히려는 시도 막기: 계정마다 5번 틀리면 10분 잠기고, 전체에서 한 시간에 30번 넘게 틀리면 그 시간 동안 가입을 막습니다.
5. 교사 빼기: 구글 계정은 `config/teachers`의 `emails`에서 지우고, 이메일·비밀번호 계정은 `teacherAccounts/{uid}` 문서를 지우거나 `disabled: true`를 넣습니다(Authentication에서 계정을 지워도 됩니다). 누가 언제 가입했는지는 `teacherSignups` 컬렉션에 남습니다.
6. 문구가 새어 나갔으면 `TEACHER_SIGNUP_CODE`를 바꾸고 다시 배포하세요.

### 모델 선택 (OpenAI)
`functions/.env`의 `OPENAI_MODEL`로 정합니다. 기본값은 **`gpt-5-mini`**(GPT-5 계열의 균형 모델)입니다.
- GPT-5 계열은 추론 모델이라 `max_tokens`와 `temperature`를 받지 않습니다. 코드(`functions/openai.js`)가 모델 계열에 맞춰 `max_completion_tokens`와 `reasoning_effort`로 자동 변환하며, GPT-4 계열도 그대로 쓸 수 있습니다.
- **용도별로 모델을 나눌 수 있습니다**: `PERSONA_MODEL`(1단계 인물 대화 전용, 기본 `gpt-5`), `SCENARIO_MODEL`(5단계 시뮬레이션만 더 강한 모델, 예: `gpt-5`), `GUARD_MODEL`(상위 AI 감독자 전용).
- `REASONING_EFFORT`(기본 `low`)는 대화 응답 속도용입니다. 5단계 시뮬레이션은 코드에서 `medium`으로 고정됩니다. 응답이 느리면 `minimal`, 품질이 아쉬우면 `medium`을 시도하세요.
- 정확한 모델명은 OpenAI 대시보드의 Models 페이지에서 확인하세요. 새 버전이 나오면 이름만 바꿔 `firebase deploy --only functions`를 다시 실행하면 됩니다.
- 비용은 모델과 추론 사고량(reasoning 토큰도 출력 토큰으로 과금)에 따라 달라집니다. 1단계 대화는 인물 응답과 감독자 검사로 호출이 2번이므로, 수업 전에 OpenAI 대시보드에서 사용량 한도(Usage limits)를 설정해 두세요.

### 3. 첫 점검
1. `/teacher.html`에서 구글 로그인 → "점검 (교사 전용)" 탭에 인물 9명이 보이는지 확인
2. 수업 만들기 → 6자리 코드 확인 → 다른 기기(휴대폰)에서 `/` 접속해 코드·모둠 번호·별명으로 입장
3. 학생 화면에서 편지를 읽고 인물과 바로 대화, 교사 화면 "수업 현황"에서 접속·단계와 대화 기록, 감독자 판정(`guard`) 확인
4. 리허설이 끝나면 `functions/.env`의 `ALLOW_UNVERIFIED_PERSONAS`를 지우거나 `false`로 바꾸고 `firebase deploy --only functions`

> Analytics는 연결하지 않았습니다(학생 대상 서비스). 웹 설정값의 `apiKey`는 프로젝트 식별용 공개 값이며, 접근 통제는 Firestore 보안 규칙과 Cloud Functions가 담당합니다.

2. 수업을 열면 위에 수업 코드가 있고, 아래에 세 가지 작업 탭이 있습니다.

   - **자료 관리**: 2단계에서 학생이 보는 '실제 사건 자료'를 이 수업에 맞게 **추가·수정·삭제·순서 바꾸기** (아래 설명)
   - **수업 설정**: 수업 이름·모둠 수, **학생별 인물 질문 횟수**, **모둠당 AI 한도(3~5단계)**, **웹 검색 켜기/끄기(1단계 인물·3단계 검색 도우미)**, **자동 닫힘 시간**, 학생 입장 안내문 복사, **수업 복제**, 수업 삭제
   - 진행 현황 맨 위의 **확인이 필요해요**: AI 오류가 난 모둠, AI 한도(80%)에 가까운 모둠, 감독자 개입이 잦은 모둠, 개인정보로 보이는 입력, 수업 중 10분 넘게 접속이 없는 학생이 자동으로 표시됩니다.
   - 수업 위쪽의 **수업 닫기/열기** 버튼: 닫으면 학생이 입장할 수 없고, 들어와 있던 학생도 로그아웃되어 AI·저장을 쓸 수 없습니다. 기록은 보존되며 언제든 다시 열 수 있습니다. 수업이 끝나면 닫아 두세요.
3. 학생에게 `/` 주소, 수업 코드, 모둠 번호를 안내합니다(수업 설정의 **안내문 복사** 사용). 학생은 **별명 + 비밀번호**로 입장합니다.
4. 인물·자료의 근거와 출처는 **인물·자료 점검** 탭에만 있습니다(접혀 있음). 학생에게는 보이지 않습니다.

### 수업 운영 편의 기능
- **수업 복제**: 이름·모둠 수·설정과 고친 자료를 새 수업(새 코드)으로 가져옵니다. 학생과 기록은 가져오지 않습니다.
- **자동 닫힘**: 마지막 학생 접속 후 정한 시간(1·2·4·8·24시간)이 지나면 수업이 자동으로 닫힙니다(30분마다 확인하는 정기 작업, 그리고 입장 시도 때에도 확인). 다시 열면 시간을 새로 셉니다. 정기 작업에는 **Cloud Scheduler**가 필요하며 `firebase deploy` 때 자동으로 켜집니다(Blaze 요금제).
- **익명 계정 정리**: 학생이 로그아웃·재입장하며 쌓이는 익명 계정 중 30일 넘게 쓰지 않은 것을 매주 일요일 새벽에 지웁니다(교사의 구글 계정은 건드리지 않음). 학생 기록은 영향 없습니다.
- **웹 검색 도메인 제한**: `functions/.env`의 `SEARCH_ALLOWED_DOMAINS`에 허용할 도메인(쉼표)을 적으면 그 사이트에서만 찾습니다. 비우면 제한이 없습니다. 너무 좁으면 '못 찾음'이 늘어납니다.

### 기다리는 동안·연결 상태 (학생·교사 화면)
- AI 답을 기다리는 동안 **움직이는 표시(고리·점·막대), 흘러가는 초, 단계별 안내 문구**가 나옵니다. "연결은 살아 있어요"라는 문구와 함께 시간이 지날수록 문구가 바뀌어(예: 8초 뒤 "자료를 확인하고 있어요", 25초 뒤 "평소보다 오래 걸려요", 70초 뒤 "최대 5분까지 기다려요") **멈춘 것인지 기다리는 것인지** 구분할 수 있습니다. 응답이 5분 안에 오지 않으면 오류로 알려 줍니다. (`public/wait.js`, 인물 대화·3~5단계 AI·교사의 연결 점검·자료 불러오기에 적용)
- 인물 대화에서 답을 못 받으면 오류 말풍선과 **다시 보내기** 버튼이 나옵니다(같은 질문을 다시 보냄).
- 헤더에 **연결·저장 상태**(연결됨 / 저장 중… / 저장됨 / 연결 끊김)가 보이고, 인터넷이 끊기면 빨간 띠가 떠서 "연결되면 자동으로 저장된다, 창을 닫지 말라"고 알립니다. 저장 중이거나 아직 못 올린 입력이 있는데 창을 닫으려 하면 경고합니다. (공용 PC 개인정보 보호를 위해 브라우저에 입력을 남겨 두는 오프라인 저장은 쓰지 않습니다. 연결이 끊겨도 창이 열려 있는 동안은 자동으로 다시 시도합니다.)
- 학생은 인물 대화 화면의 **대화 저장**으로 자기 대화를 글 파일로 내려받을 수 있습니다(성찰 활동용).
- 접근성: 건너뛰기 링크, 대화창 읽어 주기(role=log), 알림 role, 키보드 포커스 표시, 움직임 줄이기 설정(prefers-reduced-motion) 지원.

### 교사 편의: 모둠 이동·일괄 초기화·인물 편집·연결 점검
- **모둠 이동**(학생 표): 모둠을 잘못 고른 학생을 옮깁니다. 인물·대화·개인 정리·비밀번호가 따라가며, 옮긴 뒤에는 새 모둠 번호로 입장합니다. 이동할 모둠에 같은 별명이 있으면 막습니다.
- **일괄 비번 초기화**: 학생 표의 체크박스로 여러 명을 골라 한 번에 초기화합니다.
- **인물 편집**(수업 안의 탭): 인물의 **편지·말투·말버릇·마음속 고민·삶의 이야기·기억나는 장면·생각(의견)**을 이 수업에 맞게 고칩니다. 학생 화면, 인물 AI, 감독 AI에 모두 적용되고 다른 수업에는 영향이 없습니다. **사건의 사실(근거 진술·출처·인물 설정·입장)은 원문 대조를 거치는 부분이라 화면에서 고칠 수 없고**, 서버도 이 항목은 받지 않습니다. 수업 복제 때 함께 복사됩니다.
- **수업 전 연결 점검**(인물·자료 점검 탭): 서버 저장소, 각 AI 모델, 인물의 웹 검색이 실제로 되는지 짧게 시험하고 걸린 시간과 오류를 보여 줍니다. 비용은 아주 적습니다.

### 학생 로그인 (별명 + 비밀번호)
- 입장할 때 수업 코드, 모둠 번호, 별명, **비밀번호(4자 이상)**를 입력합니다. **처음 입장하면 그때 정한 비밀번호가 그 별명의 비밀번호**가 됩니다(같은 모둠의 같은 별명은 한 사람).
- 같은 별명·비밀번호로 다시 입장하면 인물 배정, 대화 기록, 1단계 개인 정리가 **그대로 이어집니다**(다른 컴퓨터에서도 가능). 같은 별명으로 다른 화면에서 로그인하면 앞 화면은 자동으로 로그아웃됩니다.
- 헤더의 **로그아웃** 버튼으로 끝냅니다. 공용 PC를 위해 로그인 정보는 **그 탭에만** 남아, 창을 닫으면 사라지고 새로 열면 항상 입장 화면에서 시작합니다. 30분 동안 아무 조작이 없으면 자동 로그아웃됩니다(저장된 내용은 그대로).
- 비밀번호는 서버에서 해시(scrypt)로만 저장하며 학생 화면과 교사 화면 어디에도 보이지 않습니다. 틀린 사람(접속 계정)이 5번 연속 틀리면 그 사람만 1분간 잠기고, 여러 계정으로 돌려 가며 틀려도 그 별명 전체로 누적 30번이면 5분간 잠깁니다. 같은 모둠 친구가 일부러 틀려서 다른 학생을 못 들어오게 하는 일은 막습니다(진짜 주인은 다른 계정으로 들어올 수 있음). 잠금은 **비번 초기화**로도 풀립니다.
- **비밀번호를 잊은 학생**: 진행 현황의 학생 표에서 **비번 초기화**를 누르면, 그 학생이 같은 별명으로 다시 입장하면서 새 비밀번호를 정합니다. 하던 내용은 유지됩니다.
- 이 기능이 생기기 전에 입장한 학생도 같은 별명으로 입장하면서 비밀번호를 정하면 이어집니다.

### 자료 관리 (2단계 실제 사건 자료)
- 처음에는 **기본 자료**(원문 대조를 마친 자료)가 그대로 쓰입니다. 자료 관리에서 고치면 **그 수업만의 자료**가 되어 다른 수업에는 영향이 없습니다. 고칠 때마다 바로 저장되고 학생 화면에 반영됩니다(학생이 이미 연 화면은 다시 입장하면 바뀝니다).
- 분류(예: 사건 흐름, 제주 도민…)를 만들고 이름·보여 주는 방식(목록 / 시간 순)을 바꾸거나 지울 수 있고, 분류 안의 자료를 추가·수정·삭제·위아래 이동할 수 있습니다. 자료마다 **종류**(사실·증언·주장·의견), 시점, 내용, **출처**(매체와 날짜)를 적습니다.
- **직접 추가하거나 고친 자료는 원문 대조를 거치지 않습니다.** 학생에게는 선생님이 확인한 내용으로 보이므로 출처 칸을 꼭 적으세요(비우면 '선생님이 준비한 자료'로 표시). 심사 결과의 숫자 요약(통계 칩)은 기본 자료의 것으로 이 화면에서는 고칠 수 없습니다.
- **기본 자료로 되돌리기**로 이 수업의 변경을 모두 버릴 수 있습니다. (인물·AI 프롬프트가 쓰는 사건 배경과 인물 진술은 이 기능과 별개이며 `functions/cases/`의 사건 파일에서 관리합니다.)

### 인물은 틀릴 수 있다 (의도한 장치)
- 실제 사회 문제에서 입장이 다른 사람들은 같은 사실도 다르게 말합니다. 인물도 자기 처지에서 보고 들은 대로 말하므로, 인물의 사실 판단·가치 판단이 반드시 옳을 필요는 없습니다.
- 사건 파일의 인물마다 `beliefs`(이 인물이 사실이라고 믿는 것, 틀리거나 과장일 수 있음)를 두었습니다. 인물은 이것을 "동네 사람들이 다 그래요", "뉴스에서 봤어요"처럼 **어디서 들었는지와 함께 자신 있게** 말하고, 학생이 반대 근거를 보이면 흔들릴 수 있습니다. 단, '정부 조사로 확인됐다'처럼 공식 확인을 꾸며 내지는 않습니다.
- 바로잡는 장치는 둘입니다. ① 1단계 ③에서 여러 인물의 말을 나란히 놓고 **서로 다르게 말한 것**을 찾고, ② 2단계 ③에서 확인할 질문으로 바꿔 3단계에서 자료로 검증합니다. 어디까지 바로잡는지는 학생의 역량에 달렸고, 그 역량을 기르는 것이 이 수업의 목표 중 하나입니다.
- 감독자(guard)는 인물이 자기 믿음을 말하는 것이나 인물끼리 엇갈리는 것을 위반으로 보지 않습니다. 배경·주장·믿음 어디에도 없는 새 수치·사건을 지어내는 것만 막습니다.
- 교사는 인물 확인 화면에서 노란 상자로 각 믿음과 **실제**(교사용 메모)를 볼 수 있습니다. 학생에게는 보이지 않습니다. `docs/PERSONA_SOURCES.md`에도 함께 실립니다.

### 상위 AI(사건 규범 감독자)

인물 AI 위에 규범을 가진 감독 층이 있습니다(`charter.js`, `guard.js`).
1. **생성 단계**: 모든 인물 프롬프트에 규범이 들어갑니다 — 사건 범위(수업의 사건, 사건 파일의 `scope`), 허용 주제, 범위 밖 주제(제주 사건이라면 다른 난민 사건, 현재 정치 예측, 종교·민족 일반 논쟁 등), 날조·단정·비하·결론 유도 금지.
2. **검사 단계**: 인물의 응답이 학생에게 가기 전에 감독자 AI가 `scope`(범위 이탈) / `fabrication`(근거 없는 핵심 사실) / `kind`(주장을 사실처럼) / `overshare`(묻지 않은 정보·과다 응답) / `meta`(AI·자료 언급) / `hate` / `advice` / `personal_info` 위반 여부를 검사합니다.
   - **인물이 1인칭으로 자기 의견을 말하는 것은 위반이 아닙니다.** `advice`는 학생에게 입장을 강요하거나 한쪽을 객관적 정답이라고 단정한 경우만입니다. 감독자에게는 인물의 생각, 공통 배경, 직전 대화 3턴이 함께 주어집니다.
   - **가벼운 위반**(fabrication, kind, overshare, meta, advice)은 감독자가 **문제 부분만 같은 인물 말투로 고쳐 쓴** 응답을 보냅니다. 질문에 대한 답과 인물의 생각은 남기고, "직접 생각해 보세요" 같은 회피 문장은 쓰지 않습니다.
   - **무거운 위반**(범위 이탈, 비하, 개인정보)이나 검사 실패는 인물 말투의 짧은 안내로 대체합니다. 학생은 AI가 끼어들었다는 것을 느끼지 않고 대화를 이어 갑니다.
   - **원래 응답과 위반 사유는 교사 전용 문서(`sessions/{code}/guardlog`)에만** 남습니다. 학생이 읽는 대화 문서에는 학생에게 보인 내용만 있습니다. 감독자 호출이 실패하거나 응답 형식이 깨지면 안전 쪽(안내)으로 처리합니다.
3. 1단계 대화는 호출이 2번(인물 + 감독자) 일어나므로 비용이 약 2배입니다(인물이 웹 검색을 쓰면 더 늘어납니다). 인물 서사가 길어져 한 번 호출에 들어가는 글(입력 토큰)도 이전보다 2~3배 늘었습니다. 수업 전 OpenAI 사용량 한도를 확인하세요.
4. 한계: 감독자도 AI라 오판할 수 있습니다. 수업 전 리허설에서 범위 밖 질문, 비하 유도 질문, 자료에 없는 질문을 직접 던져 보고, 교사 로그의 `guard` 기록을 점검하세요.

### 인물의 웹 검색 (모르는 사실은 찾아 보고 답하기)

인물이 자기 자료([모두가 아는 배경]·[네가 알고 겪은 일])에 없는 **구체적 사실**(수치, 날짜, 제도의 내용, 누가 무슨 말을 했는지)을 질문받으면, 앵무새처럼 같은 말을 되풀이하는 대신 웹에서 확인하고 답합니다. (`functions/lookup.js`)
- 인물 모델에게 `lookup` 도구를 주고, 필요하다고 판단할 때만 부르게 합니다(한 응답에 최대 2번). 인물의 경험·감정·생각을 묻는 질문, 일상 대화, 범위 밖 질문에는 쓰지 않습니다.
- 검색은 OpenAI **Responses API의 `web_search` 도구**로 합니다. 범위는 수업의 사건이고(사건 파일의 `search.scope`), 제주 사건이라면 **2018년 12월 31일 이후 정보는 쓰지 않도록** 지시합니다. 믿을 만한 자료를 못 찾으면 `NOT_FOUND`를 돌려주고, 인물은 **"그건 정확히는 모르겠어요"**라고 말한 뒤 자기가 아는 것이나 생각을 이어 갑니다. 검색이 오류가 나도 같은 방식으로 모른다고 답하며 대화는 끊기지 않습니다.
- 찾은 내용은 인물의 말투로 자연스럽게 말하고('검색해 보니' 같은 말은 하지 않음), 웹 문서 속 지시문은 따르지 않는 '데이터'로만 취급합니다. 상위 AI(감독자)는 이번 응답을 위해 조회한 내용을 근거로 함께 받아, 근거가 있는 사실을 날조로 오판하지 않습니다(범위 이탈·주장 단정은 그대로 검사).
- **기록**: 검색어, 찾은 내용 요약, 출처 주소가 대화 기록에 남아 교사의 '대화 보기'에서 보입니다. 학생 화면에는 해당 말풍선 아래에 **'🔎 웹에서 찾은 내용이 쓰였어요 (출처 보기)'**가 붙어 출처를 확인할 수 있습니다(검증 습관).
- 설정: `PERSONA_WEB_SEARCH=false`로 끌 수 있고(기본 true), `SEARCH_MODEL`로 검색 호출 모델을 따로 정할 수 있습니다(비우면 `OPENAI_MODEL`). 웹 검색 도구는 호출당 별도 요금이 붙고 응답이 몇 초 더 걸립니다. 모델이 `web_search`를 지원하는지 OpenAI 문서에서 확인하세요(미지원이면 검색은 '못 찾음'으로 처리됩니다).
- 한계: 웹에서 찾은 내용도 틀릴 수 있습니다. 수업 전 리허설에서 자료에 없는 사실을 물어 보고 교사 로그의 검색 기록과 출처를 확인하세요.

### 원문 대조 (필수)

**근거 진술은 AI가 검색 결과 요약을 바탕으로 정리했습니다.** 사건 파일의 출처에 `verified: true`가 적혀 있어야 그 출처를 쓰는 인물·자료가 학생에게 보입니다.

| 사건 | 대조 상태 |
|---|---|
| 제주 예멘 (J·C·A·N, 45건) | 검증됨. 출처마다 검색 교차 확인 기록(`CROSS_CHECK`)이 있고, 확인되지 않은 진술(예: 이동 비용 1,500달러, 이의신청 48명, 대책위의 말레이시아 난민협약 발언·법무부 접촉, '서울로 가고 싶어 한다')은 빼거나 고친 뒤 검증됨으로 표시했습니다. |
| 쓰레기 수출 (W1~W21), 강서 특수학교 (S1~S13) | 검증됨. 작업 환경에서 기사 사이트에 직접 접속할 수 없어, 출처마다 웹 검색으로 기사 내용을 다시 찾아 진술과 맞춰 보았습니다. 확인되지 않은 수치·발언은 빼거나 확인된 출처로 옮겼고(예: 특수학교 인근 땅값 4.34%/4.29% 수치, 교육감 토론회 발언 삭제), 결과는 출처마다 `check`에 **[대조함]**으로 적었습니다. 원문 전문을 읽은 것은 아니어서 작은 차이는 남을 수 있으며, 학생이 3단계에서 검증합니다. |

1. `docs/PERSONA_SOURCES.md`(또는 교사 화면의 "점검 (교사 전용)" 탭)에서 출처 링크를 열어 진술과 대조합니다.
2. 틀린 진술은 `functions/cases/`의 사건 파일에서 고치고, 확인한 출처에는 사건 파일 `SOURCES`의 그 항목에 `verified: true`를 적습니다.
3. `cd functions && npm run export-sources > ../docs/PERSONA_SOURCES.md`로 점검표를 갱신하고 배포합니다.
- 리허설은 `functions/.env`에 `ALLOW_UNVERIFIED_PERSONAS=true`를 넣으면 대조 전 인물도 보입니다. 실제 수업 전에는 지우세요.
- 출처 제목 중 일부(J15, J17)는 설명 문구이며 실제 제목이 아닙니다.
- 고용주(강태호)는 직접 인터뷰 자료가 부족해 보도된 고용 상황을 바탕으로 구성했습니다. 고용주 인터뷰를 찾으면 근거를 보강하세요. 난민 인정자 본인의 장기 정착 증언은 아직 없습니다.

## 수업 전에 직접 확인할 것

- `public/app.js`의 `CHECKLIST`(7단계 성찰 10문항)는 초안입니다. 연구에서 사용하는 문항으로 교체하세요.
- 학교 네트워크에서 Firebase·OpenAI 관련 도메인이 막히지 않는지 학생 기기로 미리 접속해 보세요.
- 학생 개인정보(실명 등)를 입력하지 않도록 안내하고, 로그를 연구에 쓸 계획이면 연구윤리·동의 절차를 확인하세요.
- AI 사용 한도: 1단계 인물 대화는 **학생별** 기본 5번(`CHAT_LIMIT`, 수업 설정에서 1~50번), 3~5단계는 **모둠별** 기본 150회(`MAX_AI_CALLS_PER_GROUP`, 수업 설정에서 10~500회). AI 오류나 감독자 검사 실패로 답을 못 받은 질문은 세지 않습니다.

## 수업 전 체크리스트 (코드로 대신할 수 없는 것)
1. **연결 점검 실행**: 교사 화면 → 인물·자료 점검 → *연결·AI 점검 실행*. 모든 항목이 "정상"인지, 웹 검색이 "찾음"인지 확인합니다.
2. **원문 대조**: `functions/cases/`의 사건 파일에 있는 출처를 원문과 대조하고 `verified: true`를 적어 배포합니다(안 하면 인물과 자료가 학생에게 보이지 않습니다. 세 사건 모두 대조를 마쳤습니다. 리허설만 `ALLOW_UNVERIFIED_PERSONAS=true`).
3. **OpenAI 사용량 한도**: OpenAI 대시보드(Usage limits)에서 월 한도를 정합니다. 앱의 모둠당 한도와 별개의 안전장치입니다.
4. **리허설**: 교사 계정과 학생 화면(다른 브라우저)으로 입장해 인물 대화(자료에 없는 사실 질문 포함), 3~5단계 AI, 로그아웃·재입장, 수업 닫기를 한 번씩 해 봅니다. 교사 화면의 대화 보기에서 검색 기록과 감독자 판정을 확인합니다.
5. 수업이 끝나면 **기록 CSV**를 받아 두고 **수업 닫기**(또는 자동 닫힘), 보관 기간이 지나면 **수업 삭제**.

## 운영 점검·오류 확인
- 교사 화면의 **확인이 필요해요**(AI 오류, 한도, 감독자 개입, 개인정보 의심, 자리 비움)와 모둠 표의 **오류** 표시가 1차 알림입니다.
- 서버 로그: `firebase functions:log` (특정 함수는 `firebase functions:log --only aiRequest`). 웹 콘솔은 Google Cloud 콘솔 → 로그 탐색기에서 `resource.type="cloud_run_revision"`으로 봅니다. AI 호출 실패와 웹 검색 실패는 `console.error`로 남습니다.
- OpenAI 쪽 사용량·오류는 OpenAI 대시보드에서 확인합니다.

### 개인정보 점검과 보관
- 학생이 입력에 **전화번호·주민등록번호·이메일·학교 이름**을 적으면 막지는 않고 교사 기록에 **'개인정보 의심'** 표시를 남깁니다(대화 보기, CSV). 수업 후 확인해 학생에게 안내하세요.
- **기록 CSV**에는 감독자 판정, 개인정보 의심, 인물의 웹 검색(검색어·찾음 여부·출처)이 포함됩니다.
- **보관·파기**: 수업의 모든 기록(대화, AI 기록, 산출물)은 교사가 **수업 설정 → 수업 삭제**를 하기 전까지 Firestore에 남습니다(자동 삭제 없음). 연구나 평가에 쓸 기록은 수업 직후 CSV로 받아 안전한 곳에 보관하고, 보관 기간이 끝나면 수업을 삭제해 파기하세요. 학생 입력에는 별명과 대화 내용만 있고 실명은 받지 않습니다.

## 입장·수업 시작 속도, 휴대폰 대화

- **입장이 빠른 이유**: Firestore 읽기를 동시에 하고, 비밀번호 해시(scrypt)를 비동기로 계산해 한 반이 동시에 입장해도 서버가 멈추지 않으며, 입장 응답에 수업 내용(편지·자료·사례)을 함께 실어 `getCase`를 다시 부르지 않습니다. 입장 화면을 보는 동안 입장 기능을 미리 깨워 둡니다(콜드 스타트 완화). 입장 중에는 버튼 아래에 움직이는 "입장하는 중" 표시와 흐르는 시간이 나옵니다.
- **더 빠르게(선택)**: `functions/.env`의 `MIN_INSTANCES=1`로 두고 배포하면 입장·인물 고르기·`getCase`가 항상 켜져 있어 첫 학생도 바로 들어옵니다. 수업 시간 전후에만 1로 올리고 평소에는 0으로 두면 비용이 거의 들지 않습니다.
- **수업 시작이 휴대폰에서도 빠른 이유**: Firestore가 실시간 연결(WebChannel)이 막히면 자동으로 long-polling으로 바꾸고(`experimentalAutoDetectLongPolling`), 대기실에서는 실시간 알림과 별도로 3초마다·화면을 다시 켤 때·인터넷이 돌아올 때 서버에서 직접 시작 여부를 확인합니다.
- **휴대폰 대화 화면**: 인물과 대화하는 동안(`body.chat-mode`) 화면 전체는 고정하고 대화창 안에서만 스크롤합니다. 키보드가 올라오면 보이는 화면(`visualViewport`) 크기에 맞춰 입력창이 키보드 바로 위에 붙고, 입력 중에는 머리글·작은 단계 막대·예시 질문을 접어 대화 공간을 넓힙니다. 말풍선은 바뀐 곳부터만 다시 그리고, 보내도 키보드가 닫히지 않으며, 맨 아래를 보는 중에는 창 크기가 바뀌어도 마지막 말풍선이 계속 보입니다. 편지는 대화창 머리의 **편지** 버튼으로 다시 읽습니다.
