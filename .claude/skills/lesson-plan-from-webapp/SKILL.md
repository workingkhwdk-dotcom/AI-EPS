# 웹앱 코드로 수업지도안 만들기

이 저장소의 앱(또는 사용자가 지정한 저장소)의 **코드를 읽고**, 정해진 형식의 **A4 수업지도안 HTML**을 만든다.
전체 요구사항은 `reference/GUIDE.md`, 형식(CSS)은 `reference/plan.css`, 작동하는 생성기 예시는 `reference/build.js`·`apx.js`에 있다. **작업을 시작하기 전에 `reference/GUIDE.md`를 끝까지 읽는다.**

## 진행 순서

1. **확인**: 아래를 사용자에게 묻거나 요청문에서 읽는다. 빠진 것만 묻는다.
   - 학교급·교과·단원·성취기준, 주제(사건), 차시 수와 한 차시 시간
   - 형식 참고 지도안 PDF와 전문가 검토 안내(AI 신호등 규칙)가 있는지
   - 모드는 **실제 수업 모드**(체험 모드 제외)
2. **코드 읽기**: 단계 정의, 학생·교사 화면, 사건/자료 데이터, 학교급·심화 설정, AI 호출 조건·한도, 프롬프트, 하네스를 찾는다. **앱에 없는 기능은 쓰지 않는다**(목록으로 적어 둔다).
3. **계획 제시 → 허락**: 차시·단계별 시간(5의 배수, 차시 합계 검산), 교과 역량 제안, 부록 구성을 알리고 **허락을 받은 뒤** 진행한다.
4. **화면 캡처**: 앱을 로컬에서 실행하고 서버 호출은 가짜로 바꿔 예시 데이터로 단계별 화면(교사 화면 포함)을 찍는다(`reference/cap.js`, `capt.js`, `seed.js` 참고). 앱 글꼴을 넣어 앱 모습 그대로 나오게 한다.
5. **생성**: `reference/build.js`(본문), `apx.js`(부록, 코드에서 직접 가져옴), `plan.css`를 새 저장소의 `docs/lesson-plan-src/`로 복사해 데이터를 교체한다. 결과는 단일 HTML(`docs/lesson-plan.html`), 이미지는 base64.
6. **점검**: PDF로 렌더링(`reference/pdf.js`)해 **쪽마다 눈으로 확인**한다(줄바꿈, 시작 위치, 쪽 나눔, 빈 쪽, 글자 크기). 시간 합계, 부록 번호 참조, 출처 인용을 검산하고 금지어(메모, `.js`, 확인 필요 등)를 검색한다.
7. 결과 HTML을 사용자에게 전달하고, 요청이 있으면 커밋·푸시한다. 사용자의 수정 요청이 오면 같은 방식으로 반복한다.

## 반드시 지킬 것 (요약. 전체는 GUIDE.md)

- 형식: A4, 함초롬바탕/돋움, 수업 표 4칸 20/93/12/32mm, `■ ◎ -`, 오른쪽 칸 `◆ ※`, 쪽 번호 `- n -`, **파란 글씨 금지**
- 활동은 **교사/학생/AI 배지 줄**, 간결한 **문어체**. 입력 칸·학생 답안은 **“예시” 배지** 상자. 발문은 **의도 설명 → “발문 예시”** 순서
- AI 신호등은 `◎` 뒤 대괄호 안 색 점. 단계마다 AI 역할과 선제 사고 → 최종 산출물
- 중·고 차이는 `고`/`심화` 배지와 범례. 인물이 여럿이면 인물 표와 직소Ⅱ 설명
- **본문에는 이미지 없음.** 부록 1에 화면을 흐름 순서로(한 행 한 장 + 오른쪽 설명). 부록은 각각 새 쪽, 차분한 디자인, 글자는 작지 않게
- AI 설계(프롬프트·하네스)는 **코드가 실제로 조립한 문장 그대로**, 구조화해서 공개
- 출처는 **확인된 것만**. 확인 못 한 것은 삭제하고 인용도 지운다. 확인 방법의 한계는 대화로만 알린다
- 개발자 메모·파일명·미완성 표시 금지. 줄바꿈은 어절 단위, 기호와 본문은 칸으로 나눠 내어쓰기, 쪽 나눔이 어색하지 않게
- 페이지 수는 줄이고, 필요하지 않은 부록은 넣지 않는다

## 사용자가 직접 줘야 하는 것

형식 참고 지도안 PDF, 전문가 검토 안내, 학습 목표 초안(있으면), 성취기준·교과 역량 확정. 출처 원문을 직접 대조하려면 개발 환경에서 해당 사이트에 접속할 수 있어야 한다.
