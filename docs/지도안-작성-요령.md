# 웹앱 기반 수업지도안 작성 요령

AI-EPS(제주 예멘 난민, 고1 통합사회2, 50분 3차시) 지도안을 만들고 고치며 정한 규칙을 한곳에 모은 문서입니다.
다른 수업용 웹앱으로 지도안을 새로 쓸 때 **이 문서를 처음부터 끝까지 읽고 그대로 따릅니다.**

- 결과물 예시: `docs/lesson-plan.html` (웹 주소 `https://knue-socialstudies-ai-eps.web.app/lesson-plan.html`)
- 생성기 예시: `docs/lesson-plan-src/` (`build.js` 본문, `apx.js` 부록, `plan.css` 형식, `cap.js`·`capt.js`·`capa.js` 화면 촬영, `pdf.js` 점검)
- 다른 저장소에서 부를 때: “`workingkhwdk-dotcom/AI-EPS` 저장소의 `docs/지도안-작성-요령.md`를 참고해서 지도안을 써 줘.”

---

## 1. 한 줄 요약

> 웹앱 코드를 **실제 수업 모드** 기준으로 읽고, 정해진 **A4 형식**(정보 표 → 범례 → 4칸 수업 표 → 수업 안내판 → 부록)으로 **단일 HTML** 하나를 만든다.
> 내용은 **코드와 앱 화면에 있는 것만** 쓰고, 독자는 **AI를 잘 모르는 현장 교사**이므로 **쉽고 간결하게** 쓴다.

## 2. 시작 전에 정할 것 (사용자에게 확인)

| 항목 | 예(AI-EPS) | 비고 |
|---|---|---|
| 대상 앱 | 저장소의 웹앱 코드(`functions/`, `public/`) | 코드를 읽을 수 있어야 함 |
| 모드 | 실제 수업 모드 | 체험 모드 기능은 쓰지 않음 |
| 학교급·교과·단원·성취기준 | 고1, 통합사회2, Ⅳ-2, [10통사2-04-02] | |
| 주제 | 제주 예멘 난민(2018) | 앱의 사건 데이터 |
| 차시·시간 | 3차시 × 50분 | 학교급에 따라 45분 등 |
| 형식 참고본 | 사용자가 준 지도안 PDF, 전문가 검토 안내 | **형식만** 참고 |
| 학습 목표·교과 역량 | 사용자 초안을 차시에 맞게 재구성, 역량은 제안 후 확정 | 학습 목표 문장은 사용자 것을 함부로 바꾸지 않음 |

**계획(차시·단계별 시간, 교과 역량, 부록 구성)을 먼저 보여 주고 허락을 받은 뒤** 만든다.

---

## 3. 내용의 원칙

1. **형식은 참고본을, 내용은 앱 코드를** 따른다. 앱에 없는 기능(게시판, 동료 평가 등)은 쓰지 않는다.
2. 활동지를 따로 만들지 않는다. **웹앱이 올인원**이다. 입력 칸·자료·화면은 모두 앱 안의 것으로 쓴다.
3. 모형 그림과 앱이 다르면 **앱을 따른다.**
4. 학교급(중·고) 차이와 심화 활동은 코드의 설정에서 가져온다.
5. **앱 화면이 바뀌면 지도안도 같이 바꾼다**: 활동 순서, 화면 이름(칩), 부록 1 화면 캡처, 부록 4(AI 호출 조건), 부록 5(척도표·평가·세특)를 코드와 다시 맞춘다.
6. **AI 사용은 학습 목표가 아니다.**

## 4. 문서 개요 (고정 순서)

1. **본시 수업지도안 정보 표**: 학교급·학년 / 장소 / 단원·차시 / 학습 목표(차시별) / 수업 흐름 한눈에 / 교과 역량 / 성취기준 / 교수·학습 자료 / 평가(한 문단)
2. (새 쪽) **범례 표** + **수업 표**(단계별 활동)
3. 각주: AI 신호등의 뜻, 고·중·심화 배지, 시간이 부족할 때
4. (새 쪽) **수업 안내판 구성**(칠판·스마트 TV) + **부록 목차**
5. **부록**(각각 새 쪽에서 시작)
   1. 웹앱 화면 흐름
   2. 사건과 인물 구성 자료
   3. 인물 편지 전문(인물이 있을 때)
   4. AI 설계의 공개: 프롬프트와 하네스
   5. 수행평가 척도표와 평가 과정(세특 작성 방식 포함)
   6. 출처 목록
   - 필요 없는 부록은 넣지 않는다. **쪽 수는 줄인다.**

## 5. 형식 (plan.css에 들어 있음)

### 5-1. 기본
- **A4 세로**, 본문 함초롬바탕, 제목류 함초롬돋움. 쪽 번호 `- n -`. 맨 위 회색 둥근 띠 “본시 수업지도안”.
- **파란 글씨 금지.**
- 수업 표 4칸: **모형 단계(20mm) | 교수·학습 활동(93mm) | 시간(12mm) | 자료◆·유의점※·AI·디지털도구(32mm)**
- 기호: 활동 묶음 `■`, 세부 활동 `◎`, 보조 `-`, 오른쪽 칸 `◆`(자료)·`※`(유의점)·`AI`(쓰는 AI·도구).
- 시간은 **5의 배수**, 차시 합계는 정확히 50분(학교급 기준). 반드시 검산한다.

### 5-2. 범례 (수업 표 바로 위, 유형별 표)
한 줄에 섞어 늘어놓지 않고 **같은 종류끼리 한 줄**, 표시마다 **뜻을 한 줄로** 적는다.

| 줄 | 내용 |
|---|---|
| 누가 하나 | `교사` 교사가 하는 일 · `학생` 학생이 하는 일 · `AI` AI가 하는 일 |
| 어느 수업에서 | `고` 고등학교 수업에서 하는 활동(이 지도안의 기준) · `중` 중학교로 할 때 달라지는 점 · `심화` 심화 활동을 켜면 더하는 활동 |
| AI 신호등(활동 제목 뒤 [●]) | 초록 자유롭게 씀 · 노랑 먼저 생각해 쓴 뒤 정해진 범위에서만 · 빨강 쓰지 않음 |
| 읽는 법 | `웹앱 1-대화` 이 활동의 웹앱 화면(부록 1) · `예시` 실제 학생 답이 아님 · `발문 예시` 그대로 읽지 않아도 됨 |
| 오른쪽 칸 | ◆ 자료 · ※ 유의점 · `AI` 쓰는 AI와 디지털 도구 |

### 5-3. 활동 줄
- **교사 / 학생 / AI 배지 줄**로 나눠 쓴다(교사 진회색, 학생 초록, AI 호박색). 배지는 고정 폭 칸, 본문은 내어쓰기.
- 웹앱 화면 위치는 **칩**으로: `웹앱 1-대화`, `웹앱 3-가장 큰 원인`처럼 **학생 화면의 장면 이름**을 쓴다(①②③ 번호보다 알아보기 쉬움). 부록 1의 칩과 같아야 한다.
- AI를 쓰는 활동은 `◎` 제목 뒤 대괄호 안에 신호등 색 점.
- 단계마다 오른쪽 칸에 **AI 역할 이름, 학생이 먼저 할 일(선제사고) → 최종산출물**을 적는다.
- 고·중·심화 차이는 해당 문장 앞에 배지를 두고 **그 학교급의 문장만** 한 줄에 쓴다.
- 인물이 여럿이면 본문에 **인물 표**(인물+축 / 누구인가 / 기본 입장)와 **직소Ⅱ** 설명.

### 5-4. 예시 답안과 발문
- 입력 칸과 학생 예시 답안은 **“예시” 배지 상자**에 넣는다(표보다 상자·항목 목록이 깔끔하면 그렇게).
- **발문**: 먼저 교사 줄에 **발문의 의도를 한 문장**으로 쓰고, 바로 아래 **점선 둥근 상자** 안에 `발문 예시` 배지와 질문을 둔다.
  - 상자 글자는 **본문보다 1pt 작게**(본문 9.7pt → 8.7pt), 이탤릭 쓰지 않음.
  - 발문은 학생에게 실제로 하는 말투로 짧게: “그 나라는 제주와 무엇이 다른가요? 우리에게 그대로 써도 될까요?”
  - 단계마다 꼭 필요한 핵심 발문만. 교사 발화를 길게 쓰지 않는다.

### 5-5. 표 디자인 (본문 인물 표, 부록 표 모두)
- 바깥 테두리는 진하게(1.2px), **안쪽 선은 옅게**, 머리줄은 차분한 회청색 바탕 + 굵은 아래선.
- 칸 여백 넉넉히, 첫 칸(항목 이름)은 돋움 굵게. 첫 칸이 긴 문장인 표(예: 진술)는 굵게 하지 않는다.
- **짧은 칸(종류, 출처, 축, 단계 번호)은 가운데 정렬**, 빈 칸은 `—`.
- 표마다 **칸 너비를 따로 정한다.** 머리글이 두 줄로 꺾이거나 단어가 중간에서 끊기면 너비나 머리글을 고친다(예: ‘인물(입장의 축)’ → ‘인물’, 축은 이름 아래 작게).
- 영어 이름·모델 이름·‘6·7’ 같은 짧은 표기는 **줄바꿈 없이**(nowrap).
- 한 칸에 조건이 여럿이면 **글머리 목록**, 보충 설명은 작은 글씨.
- 오른쪽 테두리가 인쇄에서 잘리지 않는지 PDF로 확인한다(표 너비 `calc(100% - 1px)`, 바깥선은 칸 테두리로).

### 5-6. 가독성
- 한글은 **어절 단위 줄바꿈**(`word-break: keep-all`). 칩·괄호·시간은 한 덩어리.
- 기호와 본문, 배지와 본문은 **칸으로 나눠 내어쓰기**.
- 양쪽 정렬로 글자 사이가 벌어지는 곳은 왼쪽 정렬. 줄 간격은 표 1.5, 본문 1.6 안팎.
- 부록 글자도 작지 않게(표 9pt 안팎).
- 쪽 나눔: 제목이 쪽 끝에 홀로 남지 않게, 표 줄·상자·활동 줄이 중간에서 잘리지 않게.

## 6. 문체 (가장 많이 고친 부분)

독자는 **AI를 잘 모르는 현장 교사**다. 읽고 바로 납득되게 쓴다.

1. **문어체, 짧고 깔끔하게.** 같은 뜻을 더 짧게 쓸 수 있으면 짧게 쓴다.
   - “실제 보도에 근거해 만든 가상 인물이며 실존 인물이 아님을 알린다” → “실제 보도를 바탕으로 만든 가상 인물임을 알린다”
   - “실천을 의무로 부과하지 않으며, 계획을 실제로 외부에 전하려면…” → “실천은 의무가 아니며, 계획을 밖에 전하려면…”
2. **사족과 중복을 지운다.** 활동 칸과 유의점 칸에 같은 말을 두 번 쓰지 않는다(정의, ‘AI는 참고 자료’ 같은 말은 한 곳에만).
3. **AI 투·번역투 금지.** 명사를 줄줄이 잇지 않는다.
   - “갈등이 생기는 지점을 문제의 출발점으로 삼도록 묻는다” → “서로 부딪히는 곳에서 모둠의 문제를 찾게 한다”
   - “적용 가능성을 판단하도록” → “우리에게 맞는지 따져 보게 한다”
   - “신뢰성·정확성·최신성을 따지고” → “믿을 만한지, 정확한지, 최근 것인지 따지고”
   - “최종 선정은 모둠이 결정함” → “최종 해결책은 모둠이 정함”
   - ‘~을 통해’, ‘다양한’, ‘효과적으로’, ‘~하는 것이 중요하다’, ‘~하도록 묻는다’의 반복을 피한다.
4. **전문 용어는 쉬운 말로.** 꼭 써야 하면 처음 나올 때 풀어 쓴다.
   - 하네스 → AI 안전장치, 호출 → AI에게 한 번 묻는 일, 사고량 → AI가 답하기 전 생각하는 정도, 정밀 모델 → 더 똑똑한 AI, 가중 카파 → 우연히 맞은 경우를 뺀 일치도, 트랜잭션 → (설명으로 바꿈) “여러 학생이 동시에 눌러도 한도를 넘지 않게 센다”
   - 코드 이름(`JSON`, `category`, `sources`, `tradeoff`, `beliefs`, `mockery` 등)은 설명 글과 표에 노출하지 않고 한국어로 바꾼다. (프롬프트 전문 안은 예외)
   - AI 관련 부록 앞에는 **‘낱말 풀이’ 표**(AI 모델, 프롬프트, 호출, 서버, 하네스, 감독자 AI, 사고량, 정해진 형식)를 둔다.
5. 학생 화면의 말(“처음 내 생각”, “가장 큰 원인”)은 그대로 인용해 교사가 화면과 맞춰 볼 수 있게 한다.
6. 사실과 다른 설명이 없는지 코드와 대조한다(예: 버튼이 나타나는 조건, AI 호출 조건, 한도 기본값).

## 7. 부록별 요령

### 부록 1. 웹앱 화면 흐름
- **본문에는 이미지를 넣지 않는다.** 화면은 모두 여기에.
- 활동 순서대로, **한 행에 화면 한 장 + 오른쪽에 칩·제목·화면/교사/학생 설명**. 교사 화면(수업 만들기, 진행 현황)과 수업 후 평가 화면(AI 채점, 확인, 세특 쓰기, 학생에게 공개)도 넣는다.
- 화면은 **우리 앱을 실제로 실행해** 찍는다: 서버 호출은 가짜로 바꾸고 예시 데이터를 채움, 앱 글꼴 포함, 태블릿 세로·2배 해상도, 헤더와 단계 탭이 보이게.
- 화면이 시연용 예시 데이터임을 머리말에 밝힌다.

### 부록 2. 사건과 인물 구성 자료
- 구성 원칙(짧은 표), 사건 개요·범위, 공통 배경(진술 / 종류 / 출처), 인물 한눈에 표(이름 / 축 / 역할 / 입장 / 틀릴 수 있는 믿음).

### 부록 3. 인물 편지 전문
- 편지지 느낌의 차분한 상자, 두 단.

### 부록 4. AI 설계의 공개
- 맨 앞 **낱말 풀이** → 단계별 AI 한눈에 보기(역할 앞 신호등 점, 조건은 목록) → 하네스(AI 안전장치) 설명 → 1단계 처리 순서 → 프롬프트 전문 → 한계와 교사가 확인할 점.
- 프롬프트는 **코드가 실제로 조립한 문장 그대로** 가져온다(손으로 옮기지 않음). 카드(번호·제목) → 쓰이는 곳/입력/출력/모델 → `[라벨]`별 구조화. 수업 중 채워지는 자리는 노란 표시.
- 카드의 ‘출력’ 칸도 쉬운 말로(예: “판정(통과 여부, 위반 종류, 이유, 고친 답, 학생 태도)”).

### 부록 5. 수행평가 척도표와 평가 과정
- 척도표는 **앱의 척도표 코드에서 그대로** 생성한다(항목 이름·단계 표기는 학생 화면의 장면 이름과 같게).
- 평가 개요 → 척도표 → 웹앱의 평가 과정(AI 채점 → 확인 → 세특 쓰기 → 학생에게 공개) → AI가 점수를 정하는 조건 → 채점 방식과 신뢰도 점검 → 유의 사항.
- **세특 작성 방식**: 평가척도표의 수준·평가 근거·교과 역량을 근거로, 학생 글을 인용하거나 요약하지 않고 **교사의 말로 다시 쓴다**. 점수를 확정한 뒤에 만들어야 수준이 맞는다.
- 척도표 Word 파일이 필요하면 같은 코드에서 생성한다(`tools/build-rubric-docx.py` 참고).

### 부록 6. 출처 목록
- **확인된 자료만** 싣는다. 끝내 확인하지 못한 것은 지우고 그 인용 표시도 지운다.
- 확인 방법의 한계는 문서가 아니라 **대화로** 알린다.

## 9. 제작 절차

1. **코드 읽기**: 단계·장면 정의, 학생·교사 화면, 사건/자료 데이터, 학교급·심화 설정, AI 호출 조건·한도, 프롬프트, 하네스, 척도표·평가·세특 코드. 앱에 없는 기능 목록을 따로 적는다.
2. **계획 제시 → 허락.**
3. **화면 캡처**: `cap.js`(학생), `capt.js`(교사), `capa.js`(평가). 결과는 `shots/`에 저장되고 쓸 화면만 `img/`로 복사, 안 쓰는 이미지는 지운다. (Playwright는 저장소의 테스트용이 아니라 전역 설치본으로 실행)
4. **생성**: `node build.js` → `docs/lesson-plan.html`과 웹 배포용 `public/lesson-plan.html`(같은 파일). 이미지는 base64로 넣어 파일 하나.
5. **PDF로 렌더링해 쪽마다 눈으로 확인**(`node pdf.js out.pdf`): 줄바꿈, 시작 위치, 쪽 나눔, 빈 쪽, 글자 크기, 표 테두리, 쪽 수 변화.
6. **검산**: 차시별 시간 합계, 부록 번호와 본문의 ‘부록 n’ 참조, 출처 인용, 금지어 검색(“메모”, “.js”, “확인 필요”), 코드 이름 노출 여부.
7. 사용자 검토 → 수정 반복 → 커밋. 웹에서 보려면 Hosting 배포(`firebase deploy --only hosting`).

## 10. 최종 점검표

- [ ] 모든 내용이 코드/앱에서 왔고, 앱 화면이 바뀐 곳까지 반영되었다
- [ ] 차시별 시간 합계가 맞고 5의 배수다
- [ ] 범례가 유형별 표이고 표시마다 뜻이 적혀 있다
- [ ] 활동 줄은 배지·문어체·간결, 칩은 장면 이름이고 부록 1과 같다
- [ ] 예시 답안에 “예시” 배지, 발문은 의도 한 문장 + 점선 상자(1pt 작게)
- [ ] 표는 같은 디자인이고 머리글·단어가 어색하게 끊기지 않는다
- [ ] 사족·중복·AI 투·번역투가 없고, 전문 용어는 쉬운 말로 풀었다
- [ ] AI 부록에 낱말 풀이가 있고 설명 글에 코드 이름이 없다
- [ ] 프롬프트 전문은 코드 그대로다
- [ ] 출처는 확인된 것만이다
- [ ] 개발자 메모·파일명·미완성 표시가 없다
- [ ] PDF로 쪽마다 확인했고 쪽 나눔이 자연스럽다
- [ ] 인쇄 안내: Chrome/Edge, A4, 머리글·바닥글 끄기, 배경 그래픽 켜기

| 클래스 이름 충돌로 빈 쪽 | 이름 겹치지 않게, 쪽 수 점검 |
