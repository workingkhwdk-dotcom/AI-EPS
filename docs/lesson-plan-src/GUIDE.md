# 웹앱 코드로 수업지도안 만들기: 요구사항과 제작 지침

AI-EPS(제주 예멘 난민, 고1 통합사회2, 50분 3차시) 지도안을 만들며 사용자가 요구한 사항을 모아 정리한 문서입니다.
다른 저장소의 웹앱 코드로 **같은 개요와 형식의 지도안**을 만들 때 그대로 지침으로 쓸 수 있습니다.
(맨 아래 “바로 붙여 넣는 요청문”과 “다른 방법”도 참고)

---

## 1. 한 줄 요약

> 웹앱을 **실제 수업 모드** 기준으로 읽고, 정해진 **A4 지도안 형식**(표 4칸 + 활동 줄 + 부록)에 맞춰 단일 HTML 하나로 만든다.
> 내용은 **코드와 앱 화면에서 가져온 것만** 쓰고, 개발자 메모는 넣지 않는다. 사용자는 브라우저에서 PDF로 인쇄한다.

---

## 2. 시작 전에 정할 것 (사용자에게 확인)

| 항목 | 이번 작업의 값 | 비고 |
|---|---|---|
| 대상 앱 | 저장소의 웹앱 코드(`functions/`, `public/`) | 코드를 읽을 수 있어야 함 |
| 모드 | **실제 수업 모드** (체험 모드 제외) | 체험용 기능을 본문에 쓰지 않음 |
| 학교급·교과·단원 | 고등학교 1학년, 통합사회2, Ⅳ-2 국제 사회와 평화 | 성취기준 코드 포함 |
| 주제 | 제주 예멘 난민(2018) | 앱의 사건 데이터에서 |
| 차시·시간 | 3차시 × 50분(고등학교) | 학교급에 따라 45분 등으로 변경 |
| 형식 참고본 | 사용자가 준 이전 지도안 PDF, 전문가 검토 안내 PDF | **형식만** 참고, 내용은 앱에서 |
| 교과 역량 | 제안안을 보여 주고 사용자가 확정 | 비판적 사고력 등 5개 |

작업 전에 **계획과 방법을 먼저 알리고 허락을 받는다.**

## 3. 사용자가 요구한 사항 (누적, 분류별)

### 3-1. 내용의 출처
1. **형식과 모양만** 사용자가 준 예시를 따르고, **내용은 우리 앱 코드에 있는 것**을 쓴다.
2. 앱 기능에 **없는 것은 쓰지 않는다**(예: 앱에 없는 공유 게시판, 동료 평가, 신고 기능).
3. 학습지·활동지를 따로 만들지 않는다. **웹앱이 올인원**이므로 입력 칸, 화면, 보조 자료도 앱 안에서 처리하는 것으로 쓴다.
4. 모형 그림과 앱이 다르면 **앱을 따른다**(예: 모형에는 없는 ‘생각 도우미’가 앱에 있으면 앱 기준).
5. 학교급(중/고) 설정과 심화 활동은 코드의 설정값(예: `level.js`)에서 가져온다.

### 3-2. 지도안 형식(고정)
1. **A4 세로**, 본문 글꼴 함초롬바탕, 제목류 함초롬돋움.
2. 맨 위에 회색 둥근 띠 “본시 수업지도안”, 아래 쪽 번호 `- n -`.
3. 정보 표: 학교급·학년 / 장소 / 단원·차시 / 학습 목표 / 수업 흐름 한눈에 / 교과 역량 / 성취기준 / 교수·학습 자료.
4. 수업 표는 4칸: **모형 단계(20mm) | 교수·학습 활동(93mm) | 시간(12mm) | 자료◆·유의점※·AI·디지털도구(32mm)**.
5. 기호 규칙: 활동 묶음 `■`, 세부 활동 `◎`, 보조 항목 `-`, 오른쪽 칸 `◆`(자료)·`※`(유의점).
6. **AI 신호등**(초록/노랑/빨강)은 `◎` 뒤 대괄호 안에 **색 점**으로 표시하고, 헤더와 각주에 뜻을 적는다.
7. 단계마다 **AI의 역할(이름), 학생이 먼저 해야 하는 일(선제 사고) → 최종 산출물**을 오른쪽 칸에 적는다.
8. **파란색 글씨는 쓰지 않는다.**
9. 웹앱 화면 위치는 `웹앱 2-①`처럼 **칩**으로 표시한다(부록 1 화면과 같은 이름).

### 3-3. 학습 목표
1. 사용자가 준 학습 목표(지식·기능·가치태도)를 **차시 수에 맞게 재구성**한다.
2. 각 차시 제목 아래 ①②…로 쓰고, 끝에 (지식, 이해)처럼 영역 표시.
3. **내어쓰기**: 둘째 줄이 본문 시작점에 맞는다(번호 칸을 따로 둔 격자).
4. **AI 사용은 학습 목표가 아니다.**

### 3-4. 시간 배치
1. 한 차시는 **정확히 50분**(학교급 기준).
2. 활동 시간은 **5·10·15·20분처럼 5의 배수**. 1~4분 단위 금지(“5분씩 끊으라”는 뜻이 아님).
3. 차시별 합계를 반드시 검산한다.

### 3-5. 활동 문장 쓰기
1. **(교사)/(학생)/(AI)** 줄로 나눠 쓴다. 이름표는 **배지**(교사 진회색, 학생 초록, AI 호박색)로, 줄바꿈 없이 고정 폭 칸에 둔다.
2. **간결하고 명확하게.** 길게 서술하지 않는다.
3. 웹앱의 **입력 칸과 학생 예시 답안**을 작은 상자로 보여 준다. 반드시 **“예시”** 배지를 붙인다.
4. **문어체**로 쓴다. 구어체 금지(예: “내 말로” → “자신의 말로”, “(나만 봄)” → “(본인에게만 공개)”).
5. **발문**은 허용: 단, **발문의 의도(의미)를 먼저 한 문장으로 설명**하고, 이어서 “발문 예시” 배지와 함께 큰따옴표·이탤릭으로 제시한다. 말 그대로 쓰지 않아도 된다는 점을 범례에 적는다.
6. **교사 발화를 길게 쓰지 않는다.** 수업의 단계에서 중요한 발문만 둔다.

### 3-6. 중·고 차이, 인물 소개
1. 중학교와 **다른 부분(고등학교 특성)**은 `고` 배지, **심화 활동**은 `심화` 배지로 표시하고 **범례**를 둔다.
2. 사건에 **인물이 여럿**이면 지도안 본문에 **인물 표**(이름·입장의 축·누구인가·기본 입장)를 넣어 한눈에 보이게 한다.
3. **직소Ⅱ 구조**를 설명한다: 학생이 모든 인물의 편지를 읽고 → 서로 다른 인물을 골라 인터뷰 → 모둠에서 합쳐 다각도로 문제를 정한다.
4. “수업 흐름 한눈에”에 차시별 단계·시간을 요약한다.

### 3-7. 범례
수업 표 위에 한 줄 범례: 교사·학생·AI 배지, 고·심화 배지, 웹앱 칩, 예시 배지, 발문 예시 배지.

### 3-8. 본문과 부록의 역할
1. **본문에는 이미지를 넣지 않는다.** 화면은 모두 부록으로.
2. **부록 1**(지도안 바로 다음): 웹앱 화면을 **수업 흐름 순서**로. **한 행에 이미지 한 장 + 오른쪽에 화면의 뜻, 교사·학생 활동**.
3. 화면 이미지는 **우리 앱 코드를 실제로 실행해 찍는다**(교사 화면 포함). 다른 앱 그림 금지. 입력 내용은 예시 데이터이므로 그렇게 밝힌다.
4. 부록은 **각각 새 쪽에서 시작**하고, 본문과 어울리는 **차분한 디자인**(회색 띠, 책 아이콘). 튀거나 투박하지 않게.
5. 부록 구성(이번 작업 기준, 필요 없는 것은 줄임):
   1. 웹앱 화면 흐름
   2. 사건과 인물 구성 자료(구성 원칙, 사건 범위·공통 배경, 인물 한눈에 표)
   3. 인물 편지 전문(편지지/핀으로 꽂은 종이 느낌의 테두리)
   4. **AI 설계의 공개**(프롬프트와 하네스): 단계별 AI 표, 통제 장치 목록, 처리 순서, 프롬프트 전문, 한계
   5. 출처 목록
6. **AI 설계의 투명한 공개**가 이 모형에서 중요하다. 프롬프트는 **코드가 실제로 조립한 문장 그대로** 가져온다(손으로 옮기지 않는다).
7. 프롬프트는 **구조화**해서 보여 준다: 카드(번호·제목) → 쓰이는 곳/입력/출력/모델 → `[라벨]` 항목별 칩과 글머리표·번호 목록. 수업 중 채워지는 자리는 노란 표시. 반복되는 공통 지침은 “…와 같음”으로 줄인다.
8. **페이지 수를 줄인다.** 꼭 필요하지 않은 부록(예: 인물별 구성 카드 전체, 자료 색인)은 뺀다.

### 3-9. 출처
1. 출처 목록은 **모두 확인된 자료만** 싣는다. **끝내 확인하지 못한 것은 삭제**하고, 그 출처를 인용한 표시도 함께 지운다.
2. 일부만 확인되어도 확인으로 보고 남긴다(날짜 등 빈 곳은 확인한 값으로 채운다).
3. 확인 방법의 한계(직접 접속 불가, 검색으로 대조)는 **사용자에게 대화로 알리고**, 문서에는 쓰지 않는다.

### 3-10. 가독성(가장 자주 지적됨)
1. **글자가 어색하게 끊겨 줄이 달라지면 안 된다.** 한글은 **어절 단위**로만 줄바꿈(`word-break: keep-all`). 짧은 괄호·칩·시간 표기는 한 덩어리(`nowrap`).
2. **시작 위치가 맞아야 한다.** 기호(■ ◎ ※ ◆ - 1) 등)와 본문을 **칸으로 나눠 내어쓰기**한다. 이름표와 본문도 칸으로 분리.
3. 양쪽 정렬로 글자 사이가 벌어지는 곳은 **왼쪽 정렬**.
4. **줄 간격**이 일정해야 한다(표 안 1.5, 본문 1.6 안팎).
5. 표만 쓰면 단조롭다. **표가 아닌 형식이 깔끔하면 그렇게**: 예시 답안은 상자, “항목-내용” 쌍은 항목 목록.
6. 표가 꼭 필요한 곳(여러 칸 비교: 인물 표, 시간 흐름, 출처 목록)은 표를 쓴다.
7. **부록 글자도 본문에 준해서 작지 않게**(표 9pt 안팎, 본문 10pt).
8. **A4 인쇄 때 쪽 나눔이 어색하지 않게**: 제목이 쪽 맨 아래에 홀로 남지 않기, 표·상자·활동 줄은 중간에서 잘리지 않기, 카드 제목·정보·첫 항목은 한 덩어리.

### 3-11. 금지
1. **개발자용 내용**을 넣지 않는다: 파일 이름(`xxx.js`), 검토·수정 후보, “교사 메모”, “정답 메모”, 확인 상태(일부 확인/미확인), 개발 과정의 설명.
2. 미완성 표시(확인 필요)를 남기지 않는다. 최종 문서는 **엔드 사용자(교사)가 보는 문서**다.
3. 앱에 없는 기능, 본문 속 이미지, 파란 글씨, 구어체.

## 4. 문서 개요(고정 순서)

1. 본시 수업지도안 — 정보 표(학습 목표, 수업 흐름 한눈에, 교과 역량·성취기준, 교수·학습 자료), 직소Ⅱ 설명
2. (새 쪽) 범례 + 수업 표(단계별 활동)
3. 각주: AI 신호등 뜻, 고·심화 배지, 시간 부족 시 안내
4. (새 쪽) 수업 안내판 구성(칠판·스마트 TV에 띄울 내용)과 부록 목차
5. 부록 1~5(각각 새 쪽)

단계 이름과 시간은 앱의 단계에서 가져온다. 예(이번 작업): 1단계 인물 경험 35′ → 2단계 원인 탐색 15′ / 2차시 확인 질문 5′ → 3단계 사실 확인 20′ → 4단계 대안 25′ → 5단계 시나리오 20′ → 6단계 행동계획 10′ → 7단계 비교·성찰 20′.

## 5. 제작 절차

1. **코드 읽기**: 단계(스테이지) 정의, 학생·교사 화면, 사건/자료 데이터, 학교급·심화 설정, AI 호출 조건과 한도, 프롬프트, 하네스(검사·횟수·기록)를 찾는다. 앱에 없는 기능 목록을 따로 적는다.
2. **계획 제시 → 허락**: 차시 배분, 단계별 시간, 교과 역량 제안, 부록 구성.
3. **화면 캡처**: 앱을 로컬에서 실행하고 **서버 호출은 가짜(스텁)로 대체, 예시 데이터를 채워** 단계별로 찍는다(Playwright, 태블릿 세로, 2배 해상도). 실제 앱 글꼴을 넣어 앱 모습이 그대로 나오게 한다. 교사 화면(수업 만들기·진행 현황·모둠)도 찍는다.
4. **생성기 작성**: 단계 데이터 → 본문 HTML, 부록 생성기(코드에서 직접 가져옴), CSS를 분리한다. 이미지는 base64로 넣어 **파일 하나**로 만든다.
5. **PDF로 렌더링해 눈으로 확인**(쪽마다): 줄바꿈, 시작 위치, 쪽 나눔, 빈 쪽, 글자 크기.
6. **검산**: 시간 합계(차시별 50), 부록 번호·참조, 출처 인용 일치, 금지어 검색(“메모”, “.js”, “확인 필요” 등).
7. 사용자 검토 → 수정 반복. 결과는 HTML 파일로 전달하고 저장소에 커밋한다.

## 6. 이번에 겪은 실수와 예방

| 실수 | 예방 |
|---|---|
| 앱이 아닌 그림/카드만 찍음 | 헤더·단계 탭이 보이는 **전체 화면**, 앱 글꼴 포함 |
| 본문에 이미지를 계속 넣음 | 본문은 글만, 이미지는 부록 1에만 |
| 시간이 1~4분 단위 | 5의 배수만, 합계 검산 |
| “(교\n사)”처럼 이름표 줄바꿈 | 이름표를 별도 칸(nowrap) |
| 표 칸이 좁아 단어가 끊김 | 어절 단위 줄바꿈, 열 너비 조정 |
| 양쪽 정렬로 글자 사이가 벌어짐 | 왼쪽 정렬 |
| 모든 것을 표로 제시 | 예시 상자·항목 목록 병행 |
| 개발자 메모가 문서에 남음 | 금지어 검색, 문서 문구를 사용자 시점으로 |
| 확인 안 된 출처를 상태 표시와 함께 노출 | 확인된 것만 수록, 한계는 대화로 |
| 같은 클래스 이름 충돌(예: 쪽 나눔용 `.pb`와 목록 `.pb`)로 쪽이 비어 버림 | 클래스 이름을 겹치지 않게, PDF 쪽 수 점검 |
| 부록 번호 변경 후 본문 참조가 어긋남 | 번호 바꾼 뒤 `부록 n` 참조 전수 검색 |
| 표가 한 쪽을 넘어 두 줄만 다음 쪽 | 쪽 나눔 + 글자 크기 조정 |

## 7. 최종 점검표

- [ ] 모든 내용이 코드/앱에서 왔고 앱에 없는 기능이 없다
- [ ] 차시별 시간 합계가 학교급 기준(예: 50분)과 같고 5의 배수다
- [ ] 활동 줄은 교사/학생/AI 배지, 문어체, 간결하다
- [ ] 예시 답안에 “예시” 배지, 발문에 의도 설명 + “발문 예시”
- [ ] 고·심화 배지와 범례가 있다. 파란 글씨가 없다
- [ ] 본문에 이미지가 없고 부록 1에 화면이 순서대로(한 행 한 장 + 설명)
- [ ] 부록은 각각 새 쪽에서 시작하고 글자가 작지 않다
- [ ] AI 프롬프트·하네스가 코드 그대로, 구조화되어 있다
- [ ] 출처는 모두 확인된 것만, 인용 표시도 일치한다
- [ ] 개발자 메모·파일명·미완성 표시가 없다
- [ ] 줄바꿈과 시작 위치가 어색한 곳이 없고 쪽 나눔이 자연스럽다
- [ ] 인쇄 안내(Chrome/Edge, 머리글·바닥글 끄기, 배경 그래픽 켜기)

### 방법 A. 이 생성기를 복사해서 데이터만 바꾸기 (가장 빠름)
`docs/lesson-plan-src/`를 새 저장소의 `docs/`로 복사한 뒤:
1. `plan.css`는 **그대로** 둔다(형식이 여기에 들어 있다).
2. `build.js`의 `stages[]`(단계 이름·시간·활동), 정보 표(학교급·단원·학습 목표·성취기준), 인물 표, 부록 1 화면 목록(`FL`)을 **새 앱 기준으로 교체**한다.
3. `apx.js`의 읽기 경로(사건·프롬프트 파일)와 필드 이름을 새 앱 구조에 맞춘다.

5. `node build.js` → `node pdf.js`로 확인.
