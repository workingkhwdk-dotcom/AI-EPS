AI-EPS 수업 도구

AI 활용 확장된 경험 기반 문제해결학습 모형을 한 학급이 실제로 수업에서 쓸 수 있는 웹 서비스로 만들었습니다. 학생은 실제 보도에 근거한 인물 4명과 대화하며 사건을 입체적으로 이해하고, AI는 모형이 정한 규칙 안에서만 개입합니다.

출발점구조7단계와 규칙인물 4명상위 AI현황남은 일
4명실제 보도 기반 인물(당사자·반대·지원·제도)
24건출처 (전부 원문 대조 전)
2층인물 AI + 상위 AI(규범 감독자)
29개자동 테스트 통과
먼저 알아 둘 것. 인물의 근거 진술은 웹 검색 결과 요약을 바탕으로 정리했고 기사 원문은 열람하지 못했습니다. 그래서 모든 출처가 “미검증”이며, 이 상태에서는 학생에게 인물이 보이지 않도록 서버가 막습니다. 원문 대조가 수업 전 필수 작업입니다.

1. 출발점: 델파이 결과가 요구한 것

1·2차 델파이에서 전문가들이 반복해서 지적한 문제를 서비스 기능으로 옮겼습니다. 모형의 취지는 지키되, 설문 의견이 가리킨 약점을 구현에서 보완하는 방향입니다.

전문가 지적서비스에서의 대응
AI 페르소나가 기존 영상 자료와 무엇이 다른가실제 보도·인터뷰에 근거한 인물에게 학생이 질문하고, 질문에 따라 사건이 구체화됩니다. 말마다 근거 자료 번호가 붙습니다.
가상 인물의 편향, 한 가지 유형에 그친 인물입장이 다른 인물 4명(당사자·반대·지원·제도), 인종·종교 비하 금지 규범, 상위 AI의 검사
협력·소통 역량을 구조로 강제할 방법모둠원마다 서로 다른 인물을 자동 배정(직소). 알아낸 점을 내 말로 정리해 모둠에 공유해야 전체 그림이 완성됩니다.
“AI가 매개·협업에만 개입한다”는 서술이 실제와 다름단계별 AI 역할과 선행 사고 게이트를 서버가 강제(아래 표)
AI의 판단이 권위를 갖게 되는 문제피드백에 “수용·수정·기각 + 내 말로 이유”를 요구, 모든 로그 자동 저장
연결고리(사건과 나)가 공감에 그침2단계에 연결고리 작성 칸(개인·학교·제도 층위 선택), 인물의 말과 실제 자료의 대조표

2. 서비스 구조

학생 브라우저는 OpenAI를 직접 부르지 않습니다. 모든 AI 호출은 Cloud Functions의 한 관문(aiRequest)을 거치며, 이곳에서 모형의 규칙이 실행됩니다.

학생 화면수업 코드·모둠·별명으로 입장 (로그인 없음). 1~7단계 워크스페이스
→
Cloud Functions인증 → 모둠 확인 → GYR 게이트 → 인물 AI → 상위 AI 검사 → 로그
→
OpenAI GPT인물 응답, 감독 검사, 피드백, 시나리오
Firestore수업, 모둠 산출물, AI 로그. 학생은 자기 모둠의 산출물만 수정, 로그는 서버만 기록
교사 화면수업 생성, 모둠별 진행 현황(1~7), AI 로그, 근거 진술 점검, CSV
Firebase Hosting정적 웹. 서울 리전, 파랑 계열 모바일 UI

3. 7단계와 AI 규칙 (GYR)

모형의 신호등 규칙을 “지켜야 할 약속”이 아니라 “지킬 수밖에 없는 기능”으로 만들었습니다. 2, 6, 7단계는 AI 호출 자체가 막히고, 나머지는 학생이 먼저 쓴 내용이 서버에 저장되어 있어야 AI가 열립니다.

단계AI서버가 확인하는 선행 조건AI가 하는 일
1 사건 경험Yellow모둠 사전 질문 3개 이상 저장, 배정된 내 인물에게만 질문 가능자료 기반 인물 대화
2 원인 탐색사용 안 함호출 자체 차단없음. 인물의 말과 실제 자료 대조, 연결고리, 검증 질문 작성
3 검증Yellow2단계에서 만든 검증 질문만 가능질문 하나에 답하고 “직접 확인할 점”을 제시. 학생은 출처를 붙여 수용·보류·불수용
4 대안 구상Yellow모둠 대안 30자 이상 저장강점과 약점, 더 생각할 질문만. 대안 고쳐 쓰기·순위 매기기 금지
5 미래 시나리오Yellow이해관계자 반응 예측 2개 이상 저장1·3·5년 후 시나리오 2개 (“예측이 아니라 가능한 시나리오” 표시)
6 행동계획사용 안 함호출 자체 차단없음. 이전 단계로 돌아가는 순환 경로 제공
7 공유·성찰사용 안 함호출 자체 차단없음. 우리 모둠의 AI 사용 기록과 10문항 성찰 체크리스트

게이트는 “썼는가”를 검사하지 “잘 썼는가”를 검사하지 못합니다. 글자 수만 채운 입력도 통과하므로, 교사 화면에서 저장된 선행 사고를 확인하는 것이 보완책입니다.

4. 실제 보도에 근거한 인물 4명

같은 사건을 서로 다른 당사자의 자리에서 보도록 당사자 · 반대 · 지원 · 제도 네 축에서 한 명씩 골랐습니다. 같은 처지의 여러 인터뷰는 한 인물로 융합했고, 이름·나이·고향은 만들지 않았습니다.

당사자

예멘에서 온 난민신청자

서울신문·머니투데이·알자지라 인터뷰, 인권위 상담 결과를 융합 (진술 11개)
  • 안전하게 살기 위해 왔다
  • 징집을 피해 말레이시아를 거쳐 제주로
  • 출도 제한과 단기 노무
반대·우려

불안해하는 제주 도민

상인 인터뷰, 집회 발언, 청원·여론 보도 (진술 8개)
  • 치안과 무사증 제도 우려
  • 결정 과정에서 도민이 빠졌다는 느낌
  • 청원 71만 4875명
지원

난민 지원 단체 활동가

대책위, 이주민센터, 난민인권센터, 앰네스티 (진술 10개)
  • 자립을 도와야 갈등이 풀린다
  • 민간 중심 지원의 한계
  • 현장의 신중론(“구별 어렵다”)도 반영
제도

출입국·행정 담당자

출입국청장 일문일답, 법무부 발표, 제주도 대응 (진술 9개)
  • 출도 제한, 무사증 불허국 지정
  • 심사 절차와 최종 결과
  • 인도적 체류의 의미

진술 종류 구분

모든 근거 진술에 종류가 붙어 있고(증언 8 사실 19 주장 5 의견 6), 인물은 주장과 의견을 사실처럼 말하지 않습니다. 검증되지 않은 집회 발언과 도민 설문은 “확인된 사실은 아니에요”라고 밝히게 했고, 이 구분이 3단계 검증 활동의 재료가 됩니다.

보류·제외한 후보

  • 어선·양식장 고용주: 일자리 갈등의 축이지만 직접 인터뷰 자료가 부족해 보류. 자료를 찾으면 5번째 인물로 추가
  • 난민 인정된 언론인 출신 2명: 대표성이 낮고 신원이 특정될 위험
  • 전문가·학자: 관찰자 위치라 당사자성이 낮음

5. 상위 AI: 사건 범위를 지키는 규범 감독자

인물 AI 위에 규범을 가진 감독 층을 두었습니다. 전문가가 제안한 “상위 AI와 하위 인물 AI” 이중 구조를 사건 범위 관리에 적용한 것입니다.

1
규범 (charter.js)
사건 범위는 2018년 제주 예멘 사건. 다른 난민 사건, 현재 정치 예측, 종교·민족 일반 논쟁은 범위 밖. 근거 진술 밖의 사실을 만들지 않고, 집단을 비하하지 않으며, 결론을 권하지 않습니다.
2
생성 단계
규범이 모든 인물 프롬프트에 들어갑니다. 인물은 근거 진술 안에서만 말하고 출처 번호를 붙입니다.
3
검사 단계 (guard.js)
응답이 학생에게 가기 전에 감독자 AI가 범위 이탈 근거 없는 사실 주장 단정 비하 결론 유도 개인정보를 검사합니다.
4
위반 시
응답을 학생용 안내문으로 바꿉니다. 원래 응답과 위반 사유는 교사용 로그에만 남습니다. 감독자 호출이 실패하거나 형식이 깨져도 차단 쪽으로 처리합니다.

감독자도 AI라 오판할 수 있고, 1단계 대화는 호출이 2번이라 비용이 약 2배입니다. 수업 전 리허설에서 범위 밖 질문, 비하 유도, 자료에 없는 질문을 직접 던져 보고 교사 로그의 위반 기록을 확인하세요.

6. 확인한 것과 못 한 것

확인함

  • 자동 테스트 29개 통과: GYR 게이트, 자료 구조, 감독자 판정 해석
  • 가짜 Firestore·OpenAI로 서버 전체 흐름 시험: 수업 생성 → 입장·인물 배정 → 1단계 대화 → 감독자 차단 → 로그
  • 가짜 Firebase로 학생 화면(1~7단계)을 헤드리스 브라우저에서 시험, 화면 확인
  • 미검증 출처의 인물은 학생에게 노출되지 않음

못 함

  • 기사 원문 열람: 네트워크 정책으로 차단되어 모든 근거 진술이 미검증
  • 실제 Firebase 배포, 실제 OpenAI 호출, Firestore 보안 규칙 시험(에뮬레이터 없음)
  • 학생 기기·학교 네트워크 접속 시험
  • 교사 화면의 구글 로그인 흐름

7. 남은 일

1
원문 대조 (필수)
docs/PERSONA_SOURCES.md 또는 교사 화면의 “인물·출처 점검”에서 링크를 열어 진술과 대조하고, 맞는 출처만 verified: true로 바꿔 배포합니다. 출처 제목 2건(J15, J17)은 설명 문구이므로 실제 제목을 확인합니다.
2
모둠 동시 편집 충돌 수정 (수업 전 필수)
같은 모둠 학생이 동시에 목록에 항목을 추가하면 한 명의 입력이 덮어써질 수 있습니다. 항목을 개별 문서로 저장하는 방식으로 바꿔야 합니다.
3
리허설
ALLOW_UNVERIFIED_PERSONAS=true로 학생 기기 접속, 범위 밖·비하 유도 질문 시험. 수업 전에는 이 설정을 끕니다.
4
모형 쪽 과제 (델파이 후속)
5단계 시나리오를 “AI 창작”에서 “실제 사례 비교 + 작동 기제 비판”으로 재설계할지, 6단계 실천의 범위, 연결고리 활동의 구체적 순서를 정해야 합니다.
5
자료 보강
고용주, 난민 인정자의 장기 정착 증언 등 빠진 관점을 찾아 인물과 출처를 추가합니다. 학생 입력의 자동 편향·안전 필터와 복수 모델 피드백 비교도 후속 과제입니다.

첫 수업은 7단계를 모두 돌리기 어려우므로 1~2~4단계로 범위를 줄여 시험하는 것을 권합니다.

배포 순서

1
Firebase 프로젝트 생성, Blaze 요금제 전환, Authentication(익명·구글)과 Firestore(서울) 사용 설정
2
public/firebase-config.js에 웹 앱 설정값 입력, .firebaserc에 프로젝트 ID 입력
3
firebase functions:secrets:set OPENAI_API_KEY, functions/.env에 TEACHER_EMAILS와 OPENAI_MODEL 입력
4
firebase deploy → /teacher.html에서 수업 생성 → 수업 코드와 모둠 번호를 학생에게 안내
